| 硬约束违例（质检 error） | 0 |
| 质检警告 | 0 |
| 重复地点 | 0 |
| 该有午饭却没有的天 | 0 |
| 整天不足 2 个地点的天（到达 / 离开日要求 1 个） | 0 |
| 最长空档（分钟，最大值） | 104 |
| 单段直线超过 3 公里的次数 | 19 |

改动排程器、主题或地点库后，`tests/test_eval_schedule.py` 会指出是哪份请求的哪个指标变了；确认是想要的变化，再用 `python scripts/eval_schedule.py --write-baseline` 重录。完整表格和解读见 [`docs/reports/q1-schedule-baseline.md`](reports/q1-schedule-baseline.md)。

## 五、需要真模型的评测（不在这份报告里重跑）

下面这些要本机开着 Ollama，会跑几十分钟，结果只打印，换模型或改提示词后自己重跑对比：

| 评测 | 命令 | 量什么 |
|---|---|---|
| 本地模型对比 | `python -m scripts.eval_models` | 7b 与 14b 的生成质量与耗时，结论见 [`model-eval.md`](model-eval.md) |
| 一句话填表（含模型） | `python scripts/eval_intake.py` | 主题 / 节奏的召回与多读 |
| 笔记抽取 | `python scripts/eval_notes.py` | 库内召回 / 精确率、库外地点进待核实、提示注入是否带偏 |
| 一句话改行程 | `python scripts/eval_nl_edit.py` | 做对了、只改该改的、新增地点都来自地点库 |
| 主题契合度评委 | `python scripts/eval_judge.py` | 评委能否区分「对得上」与「冒充」 |

已有结论（见 `model-eval.md`）：默认的 `qwen2.5:7b-instruct` 不比 14b 差且快 5–10 倍；剩下的硬错误是约束问题，不是模型尺寸问题。模型写的说明只是表达层，生成后逐条检查，不合格的整段丢掉换成模板，所以模型质量不影响行程是否正确。

## 六、没有覆盖的

- 真实模型输出的文笔和稳定性（见上一节，要自己跑）。
- 高德、维基媒体等外部服务的实时调用：测试用录制的数据，不打真实接口。
- 数据的「句子有没有被曲解」：脚本只能核对数字、名字和来源能不能打开，措辞要人看。
- 自动现建的城市（标准档）：价格、预约、部分闭馆日没有核对，行程里会写「以官网为准」。
