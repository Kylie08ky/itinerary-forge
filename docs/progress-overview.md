## 能做什么

- **生成**：选主题（可多选、有权重）或一条深度路线 → 算法排路线（避开闭馆日、午饭不跳过）→ 模型只写说明，模型不可用时自动用模板；后台生成，离开页面也能在「我的行程」找回。首页写一句话就能填好表单。
- **改**：拖拽、锁定、换一个、删除、撤销重做、版本保存与回滚、一句话改行程、候选池、平移日期、复制、归档。
- **交付**：PDF、长图、日历（ICS）、地图文件（KML）、Markdown / HTML、只读分享链接；手机可用，离线只读。
- **费用与出行**：住宿与预订、天气（下雨提示室内备选）、预算（逐人算优惠、汇率）、随行清单、出行中的「今天」卡片。
- **导入**：粘贴朋友的笔记或链接，自动找出地点并标出处；文件附件。
- **目的地**：巴黎和意大利十座热门城市是精校的；其他城市现建，数据是「标准档」（价格、预约、部分闭馆日没核对，行程里写明）。国内行程用高德地图。

## 一天怎么排

- **均衡 = 上午 1、下午 1、晚上 1**；轻松 = 上午 1、下午 1，晚上自由；紧凑 = 上午 1、下午 1–2、晚上 1。不自动补「顺手的小点」。
- **晚上**：黄昏夜景、游船这类；挑不到合适的就让这晚空着，不凑数。
- **午饭**：每天一定有；本身就是一顿饭的点替代「午餐（自行选餐厅）」占位。
- **一日游**（凡尔赛、迪士尼）独占一天，4 天以上才默认出现。
- **当季活动**：只在举办期里排；期外当闭馆；日期按年，明年要重查。

## 已知局限

- 现建城市只是「标准档」，国内小城的景点靠开放数据，找不到的要在候选池里点「在高德里搜」。
- 本地 7B 模型写的说明偶尔不合格，会被检查丢掉并换成模板。
- 排程是算法不是最优解：午饭前后会有 1–2 小时空档，晚上的点可能挑不到。
- 无账号、无协作；`/plans` 对所有能访问服务的人可见（自用 / 朋友用的形态）。
- 小红书只读你主动粘贴的链接，用你自己的登录状态，账号有被限流的风险。

## 完成标准

交付形态是**作品集演示加自己和朋友用**：做到「能用、能演示、有文档和评测报告」。事实只信核对过的数据；所有改动先改规格，再写验收，最后写代码。
