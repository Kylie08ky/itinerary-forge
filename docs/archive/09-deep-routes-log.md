## 一、和现有「主题」有什么不一样

| | 现有主题（如「艺术」） | 深度路线（P17） |
|---|---|---|
| 是什么 | 一个**地点池** + 权重，排程器从池里挑点 | 一条**有章节顺序的叙事**：先看什么、为什么接着看那个 |
| 选点 | 按权重、就近、开放时间填满每天 | 路线里**写死了顺序和每站要看什么**，排程器只负责塞进日期、避开闭馆、裁剪 |
| 文字 | 每个点一句话看点 | 每章有一段**背景故事**，每站有「看什么 / 为什么在这里」，章与章之间有衔接 |
| 地点 | 81 个通用点 | 通用点 + **小众点**（需要专门策展和核对） |
| 在页面上 | 新建表单的主题卡 | 新建表单里单独一块「深度路线」，选一条；行程页每天顶部是章节标题 |

深度路线**不替代**现有主题：想要「卢浮宫 + 美食 + 购物」这种混选，仍用主题；想要「跟着一条线索走」，选路线。

## 二、路线的数据结构（`data/routes/<城市>.json`）

```
Route
  id, name_zh, tagline                      「时尚：从高级定制到街头」
  thesis                                    主线，一句话：这条路线想讲清楚什么
  days: {min, suggested, max}               建议 2–3 天，最少 1 天（精华版）
  chapters: [Chapter]                       按顺序；一章 ≈ 一天的上午 / 下午或一整天
Chapter
  id, title, story                          这一章在讲什么（150–250 字），带来源
  sources: [{title, url, checked_at}]       story 的依据（维基百科条目、官方网站、书目）
  stops: [Stop]                             章内的站，有顺序
Stop
  place_id                                  必须在地点库里（通用点或新增的小众点）
  priority: core | optional                 天数不够 / 节奏紧时，先砍 optional；core 不砍
  look_for: [str]                           这一站看什么（2–3 条，带来源；不能是模型编的）
  why_here: str                             为什么这条线上要有它（一两句，带来源）
  after: place_id | null                    必须排在哪一站之后（叙事顺序；不写就章内自由）
Reading（可选）
  title, kind(book|film|exhibition), note   延伸阅读 / 观影，只列真实存在、核对过的
```

- **新增一个小众地点**和现有地点一样严格：坐标、官网（自动核对能打开）、每周闭馆日、预约要求、门票价格（带来源和核对日期）、中文名 + 当地语言名（P18 流程，来自 OSM / 维基数据）。核对不了的，不收进路线，也不让模型补。
- 路线文件有**数据闸门**测试：每个 `place_id` 存在；每章有来源；每个 core 站有 `look_for` 和 `why_here`；整条路线的 core 站在一份典型日程里不会全部撞在同一个闭馆日。

## 三、排程器怎么用路线

排程器（`app/scheduler`）现在是「从池里挑点 + 就近排序」。路线模式在前面加一步，**其余硬约束一个都不松**：

1. **分章到天**：天数 = 用户选的天数。章按顺序铺到各天（天数多于章数：长的章拆成上午 / 下午；天数少于章数：合并相邻章，优先砍 optional 站）。
2. **章内顺序**：按 `stops` 的顺序和 `after` 约束排；顺序和开放时间 / 闭馆日冲突时，只调整**同一章内**的顺序，章与章的先后不动，并在「生成说明」里写明为什么调了。
3. **裁剪**：节奏（轻松 / 均衡 / 紧凑）决定每天站数上限；超出的 optional 站先砍，再砍 core 站里权重低的（会写进说明）。
4. **硬约束照旧**：闭馆日、开放时间、午饭必须有、到达 / 离开缓冲、预订锁定的时间，全部由现有排程器和质检处理；路线不能绕过它们。
5. 排出来的行程仍是普通行程：能编辑、拖拽、导出、预算、分享；每天的 `theme` 写章标题。

## 四、模型管什么、不管什么

- **管**：把「这一天的章节故事 + 这几站的看点」连成一段读起来顺的导览（每天一段，约 120–200 字）；按用户的节奏 / 同行人（带孩子、长辈）调整措辞；一句话改路线时理解意图。
- **不管**：选哪些地点、顺序、时间、开放时间、价格、地点名、网址。导览里出现的地点名必须全部来自这一天行程的站（生成后自动检查，出现路线外的地名 / 数字 / 网址就整段丢弃，回退到策展原文）。
- **模型不可用**：直接用策展的章节 `story` + 每站 `look_for` 拼成导览，不降质量的底线；页面标「模板生成」（和现在一致）。

## 五、页面

1. **新建行程页**：主题选择区下面多一块「**深度路线**」：每条路线一张卡（名称、主线一句话、建议天数、站数、例几个站名）；选了路线，天数建议跟着变，主题选择区变灰（路线和混选主题二选一）。
2. **路线详情**（点卡片展开，不另开页）：主线、各章标题和每章的几站（只给名字和一句话），让你生成前就知道这条路线讲什么。
3. **行程页**：每天顶部是「第 N 章 · 标题」和那一天的导览；每个景点下面多一行「看什么」；页面底部有「延伸阅读」；封面写路线名。
4. **导出**：PDF / HTML / Markdown 里带章节标题、导览和看点（日历 / KML 不带长文）。

## 十一之二、你验收时的反馈：路线要灵活（2026-10-26，**这一版已改**）

- **天数不再硬限制**：你已经定了去几天，仍然可以走这条路线。路线旁边只**标注推荐**（「推荐最少 2 天 · 建议 3 天」），选的天数少于推荐 / 多于路线内容时，页面给一句提示（不拦你、不报错）：
  - 天数比推荐少：按优先级取舍（先砍可选站，再砍权重低的核心站），没排进来的站写进「生成说明」。
  - 天数比路线内容多：路线内容排在前面的几天（艺术路线最多 5 天），**多出来的天用路线对应的主题（艺术）补充**，那几天标「自由日 · 艺术主题补充」，没有导览。
- **每一站可以自己选要不要去**：路线详情里每一站前面有勾选框（默认全选），有「全选」「只留核心站」；没勾的站不排；至少留一站。生成时只带你勾的站（`route_stops`）。
- **封面显示全部路线站**：之前封面亮点卡每天只放一张；选了路线的行程，封面把路线上排进来的站都放出来（可左右划）。

## 十二、批量做路线（你 2026-10-26 的反馈：「还是一条条做？不能批量生成吗？」）

- **一条命令批量核对并写入**：`python scripts/build_route.py data/routes/drafts/*.json`。脚本替我做以前手工一页页核的事：
  1. 每个来源网址真的请求一次（维基百科取全文）；
  2. 故事、看点、理由里的年份 / 数量（3 位以上的数字）必须在**这一章 / 这一站自己引用的来源**里出现，对不上就报错、不写文件；`--explain` 列出每个数字出自哪几个来源给人复核；
  3. 延伸阅读的来源页面里必须同时有作者姓和年份；
  4. 地点都在库里、没有长期闭馆、没有重复；通过后再用运行时同一套规则完整校验。
- **脚本核对不了的**（要人看）：事实表述有没有被曲解（只查数字和来源能不能打开，不理解句子）、地点的官网开放时间和票价。这次我在脚本通过之后，又逐条对了关键句子在来源里的原文，发现并改了 3 处脚本没拦住的错：香奈儿的 1918 年是「买下康朋街 31 号」不是「开店」、花神咖啡馆来源写「1880 年代出现，确切开业日期不详」（我原来写的 1887 年是凭印象）、乐蓬马歇来源写「最早的现代百货公司之一」（不是「世界上最早」）。

## 十五、方向修正（你 2026-10-26 的反馈）：文化内容织进行程，不是前置选择（**你已「方案同意，先做 A，了解巴黎降级」**）

3. 深度路线由系统自动出：你选兴趣线（历史 / 民俗 / 美食 / 其他）或直接选路线，系统按这条线选点、排章节、写主线，作品和故事自动进来；不再要求用户挑作品。

### 十七之五、第 4 步：午餐建议（你 2026-10-28「做美食第 4 步午餐建议」）

**范围**：行程里的「午餐（自行选餐厅）」那一行（普通行程和路线行程都有；`午餐（简餐）`、一日游、已经有午餐点当午饭的那天没有这一行或不适用），在备注里写上**附近可以去的午餐点**。

**候选只用地点库里标了 `meal: lunch` 的点**（现在 8 个：普罗可布、蓝色列车、圆顶，10 月 28 日补的肖蒂埃、博芬格、利普、富凯、人类博物馆咖啡馆）：它们的开放时间有官网依据，说明里写明了是用餐的地方。不用印象里的餐厅、不用网上评分、不让模型推荐。

**挑法（纯算法，输入相同输出相同）**
- 这一天午餐前后最近的景点（上一站、下一站）到午餐点的直线距离 ≤ 1.2 公里；取两者中较近的，从近到远最多 2 个；
- 那天开放（闭馆日、当季、长期闭馆都认）；
- 这份行程里已经排了的点不再推荐；
- 写成：「附近可以去：普罗可布咖啡馆 · Le Procope（约 600 米，12:00–24:00，餐厅建议订位）；……。也可以自己选餐厅，热门餐厅记得提前订位。」开放时间没核对的写「开放时间未核对」；没有附近的点就还是原来那句，不硬凑；
- 编辑行程（移动、重排）后，重新排的那几天会按新的位置重算；
- 一日游、30 分钟简餐的午餐不写。

**诚实说明**：补充后 73 个核心景点里 56 个附近有午餐店（以前 21 个）；还没覆盖的是橘园 / 协和广场、荣军院 / 罗丹、蒙马特、运河、拉雪兹神父墓园等，蒙马特的两个风车咖啡馆官网没写午餐，没标；新加的 5 家只进地点库、不进主题（不参与排程）；富凯和人类博物馆咖啡馆官网没写开放时间，建议里写「开放时间未核对」；想让更多天有建议，要继续往地点库里加有官网依据的午餐点（路线「法式餐桌」里的新增场所就是这样来的）。
