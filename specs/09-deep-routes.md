# 09 深度游学路线（主题式文化路线）

一句话：给巴黎做**有主线、有顺序、有背景故事**的路线（现在 6 条），再把电影 / 书的故事、名菜、当季活动织进行程。路线里的每个地点和每句事实都来自核对过的来源，不信模型。

做的过程、方案反复和每一步的实现细节在 [`docs/archive/09-deep-routes-log.md`](../docs/archive/09-deep-routes-log.md)，这里只留现在的规则和验收场景。

## 一、和「主题」的区别

| | 主题（如「艺术」） | 深度路线 |
|---|---|---|
| 是什么 | 一个地点池 + 权重，排程器从池里挑 | 一条有章节顺序的叙事，顺序和每站要看什么写死 |
| 文字 | 每个点一句话 | 每章一段背景故事，每站有「为什么在这里」和「看什么」 |
| 新建页 | 主题卡，可多选混搭 | 「深度路线」按兴趣线分组（历史 / 民俗体验 / 美食 / 其他），和主题二选一 |

## 二、现有路线

| 路线 | 兴趣线 | 排法 |
|---|---|---|
| 艺术：从王室收藏到当代 | 其他 | 按章往下走 |
| 时尚：从高级定制到街头 | 其他 | 按章往下走 |
| 历史与思想：从中世纪到存在主义 | 历史 | 按章往下走 |
| 古建筑与名胜：从王权到铁与玻璃 | 历史 | 按章往下走（凡尔赛独占一天） |
| 法式餐桌：从早市到咖啡馆 | 美食 | 每天每类挑一家（`layout: pick-one`） |
| 巴黎的圣诞集市 | 民俗体验 | 按章往下走；**限定**（只在举办期里有） |

## 三、数据与规则

- **路线** `data/routes/<城市>.json`（`app/routes.py`）：路线 → 章（故事 + 来源）→ 站（`place_id`、core / optional、`look_for`、`why_here`、`after`）+ 延伸阅读。数据闸门测试：地点都在库里、每章有来源、core 站有看点和理由、没有长期闭馆的站。
- **作品** `data/culture/<城市>.json`（手工）+ `.auto.json`（维基数据批量生成）（`app/culture.py`）：电影 / 书（纪录片、播客目前 0 部）。名气 = 维基百科语言版本数，**门槛 ≥ 20**（`MIN_POPULARITY`）。
- **名菜与招牌** `data/food/<城市>.json`（`app/food.py`）：名菜门槛 ≥ 10 个语言版本；「招牌」只收来源页面里同时提到店名和菜名的。
- **当季活动**：地点库里的点带举办期、来源和核对日期；行程日期不在期内当闭馆。**按年的数据，明年要重查**。民俗只收「官方页面写明，或至少两个独立来源一致」的日期，来源之间矛盾的不收。
- **批量核对脚本**（流程都是：写提纲 → 一条命令核对 → 通过才写入）：`build_route.py`、`build_culture.py`、`build_culture_auto.py`、`build_food.py`，新增地点用 `add_route_places.py`、`add_food_places.py`、`add_paris_events.py`。脚本检查：来源能打开；故事、看点、理由里的年份和数量在这一章 / 这一站自己引用的来源里出现；延伸阅读的作者姓和年份在来源里能找到；中文名在中文维基百科查得到；核对不了的写「以官网为准」。脚本只查数字、名字和来源能不能打开，**句子有没有被曲解要人看**。

## 四、排程怎么用路线

排程器在最前面加一步，其余硬约束（闭馆日、开放时间、午饭、到达 / 离开缓冲、预订锁定）一个都不松：

1. **分章到天**：站按路线顺序一天一天往下填；闭馆的站挪到后面的日子；排不下先砍 optional，再砍权重低的 core，写进「生成说明」。
2. **天数不硬限制**：只标注推荐（「推荐最少 N 天 · 建议 M 天」）；天数多于路线内容时，多出来的天用对应主题补，标「自由日」。
3. **`pick-one` 路线**：每天从每一章里各挑一家（一个市场、一家午餐、一家下午茶、一家咖啡馆），那天闭馆就换下一家，不重复；没轮到的店合并成一条说明。
4. **一日游独占一天**：凡尔赛宫等郊区一日游不跟别的站同天、不排午饭；「至少玩多久才值得去」按这个点自己的游览时长和 5 小时取小。短行程（< 4 天）不默认带主题自带的一日游，用户自己选的「必去」不受限。
5. **用餐的站进排程**：地点有 `meal`（午餐 `lunch` / 下午茶 `tea`），排在对应时段时它**就是**这顿饭，不再另排「午餐（自行选餐厅）」；午餐不占白天名额，下午茶占下午的名额。只给说明里写明了的点打标。
6. **午餐建议**：「午餐（自行选餐厅）」那一行的备注里，列最近的至多 2 个标了 `meal: lunch`、那天开放、没排进行程的点（直线 ≤ 1.2 公里，纯算法）；附近没有就保持原句，不硬凑。

## 五、模型管什么

- **管**：把这一章的故事连成一段读起来顺的导览（80–150 字，只讲主线和衔接，不逐站复述）；理解一句话改行程的意图。
- **不管**：选点、顺序、时间、开放时间、价格、地点名、网址。导览生成后逐段检查，出现网址、价格、钟点、路线外的名字就整段丢掉，换成策展原文。模型不可用也一样出导览（页面标「模板生成」）。

## 六、页面

- **新建页**：「深度路线」卡片（主线、建议天数、站数、例子），点开看每章和每一站，每站前有勾选框（默认全选，有「全选」「只留核心站」，至少留一站）；选了路线，主题区变灰；天数和推荐不符时提示（不拦）。**限定**路线（每一站都是当季活动）卡片上标「限定」并写举办期；所选日期和举办期没有重合时提示「当前日期没有这个活动」。
- **行程页**：每天顶部是章节名（小标题只写「第 N 章」）和这一章的导览；每站下面是「为什么在这里」「看什么」「这里的故事」「招牌」；底部有「这趟旅行里的作品」（默认收起，没有故事时整块不出现）和路线卡片（主线、延伸阅读、策展说明）；改动偏离路线顺序时顶部提示。
- **「了解巴黎」参考页**（`/culture`）：只读，列作品和它带你看的地方、美食一节，只能从行程页的「更多作品」进，导航里没有。**不让用户先选作品**，故事和招牌只织进行程，不由模型写，ICS / KML 不带。
- **导出**：Markdown / HTML / PDF / 长图带章节、导览、看点、故事和招牌；分享页同行程页；今日页当前 / 下一站有故事或招牌时多一行。

## 七、验收场景

**故事（C）**

| 编号 | 场景 | 预期 |
|---|---|---|
| C1 | 行程页有故事的地点 | 多一块「这里的故事」，最多 2 条（名气大的在前），多的点「详情」 |
| C2 | 地点卡 | 列全部故事：作品名 / 作者 / 年份 / 说明 / 来源链接 |
| C3 | 「这趟旅行里的作品」 | 默认收起；按实际排进的地点汇总；没有故事时整块不出现 |
| C4–C6 | 今日页 / 导出 / 分享页 | 有故事时多一行；ICS、KML 不加 |
| C7 | 导航与新建页 | 没有「文化入门」入口和「带进行程」；`/culture` 是只读参考页 |
| C8 | 没有文化数据的城市 | 页面和导出与以前完全一样，不出现空块 |

**美食（F）**

| 编号 | 场景 | 预期 |
|---|---|---|
| F1–F3 | 有招牌的场所（Ladurée、天使之家等） | 行程、地点卡、今日页、分享页、导出里有「招牌：马卡龙」，最多 2 样；没有招牌的不出现空块 |
| F4–F5 | 参考页「美食」一节；纯博物馆日 | 名菜名点列表，没招牌的菜不写「去哪吃」；没有招牌的行程里没有「招牌」字样 |
| F6–F8 | 美食主题 4 天；下午茶的点 | 中午是路线 / 地点里的午餐点，说明写「这一站就是午餐」，那天仍是上午 1、下午 1、晚上 1；下午茶开始在 14:30–17:30；不排长期闭馆的红孩子市场 |
| F9–F11 | 「法式餐桌」生成 3 天 | 每天最多一市场、一午餐、一下午茶、一咖啡馆；第一天顶部有章介绍，之后没有；和平咖啡馆的闭馆日待核对，备注写「出发前以官网为准」 |
| F17–F19 | 艺术主题 4 天必去奥赛；只走香榭丽舍和铁塔一带；把奥赛那天的景点拖到别的天 | 午餐备注有「附近可以去：…」（距离、开放时间）；没有附近的点就保持原句；拖动后重新排的两天按新位置重算 |

## 八、已知局限

- 民俗体验只有两个有依据的活动（日期按年）；播客和纪录片作品是 0。
- 模型写的导览文笔没有在真模型上实测过，只测了「合格的用、不合格的回退」。
- 个别馆的开放时间没核对到钟点，排程可能排到接近闭馆；以官网为准。
- 路线遇到闭馆日会把站挪到别的天，章节顺序局部颠倒时「为什么这样排」里会写明。
- 午餐建议只覆盖附近有已核对午餐店的景点；要更多天有建议，要往地点库加有官网依据的午餐点。
