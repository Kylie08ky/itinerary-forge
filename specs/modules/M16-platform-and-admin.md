## 为什么

作品集需要「别人能一键跑起来」；真实使用需要备份和监控。

## 范围

后做（v1.0）：管理面板（F95）、备份 / 恢复（F96）、审计日志（F97）。

## 验收场景

**S1 P0 · 一键启动**
- 假设 一台装了 Docker 的新机器，复制 `.env.example` 为 `.env`
- 当 执行 `docker compose up`
- 那么 访问首页能生成示例行程（无 Key 时使用降级路径：基础地图 + 本地模型或样例数据），并显示清晰的配置提示

**S2 P0 · 健康检查**
- 假设 服务运行中
- 那么 `GET /healthz` 返回各依赖（数据库、模型、地图）状态，失败项不影响整体可用

**S3 P1 · 备份与恢复**
- 假设 我点击「导出备份」
- 那么 得到一个包含行程、附件的压缩包；在新实例点「导入备份」后数据一致

**S4 P1 · 管理后台**
- 假设 我以管理员登录
- 那么 看到用户数、近 7 天生成次数、模型 / 地图调用与费用估算、失败任务列表

**S5 P1 · 日志与脱敏**
- 假设 发生一次生成失败
- 那么 日志带任务 ID、步骤、耗时，但不含密码 / Key / Cookie

## 验收方式

- **自动化**：容器构建与启动冒烟测试（CI）；日志脱敏测试；备份恢复往返。
- **前端**：你在另一台机器 / 同事电脑上走一遍 S1。
