# M05 地图与地点搜索

> 版本：v0.1（每日地图 + Google）→ v0.2（全程路线、搜索、导航、聚类）→ v0.5（高德；视口探索推后，代理只写文档）
> 功能：F26 F27 F28 F29 F30 F31 F32 F33 F34 · 来源：TripStar（双引擎）+ TREK（搜索、聚类、导航）
> **现状（2026-11-06）**：✅ 已做完：每日地图、全程分色路线图、地点搜索（库内）、Google 地图导航链接 + KML、标记聚类、照片标记；**高德（K2）三批**：国内行程的地图走高德、库外地点在高德里搜、国内酒店地址定位、点了才查的真实通勤时间，国内导航链接改高德，用量自留上限；手机行程页的地图抽屉境内也用高德。视口探索、代理配置（v0.5）暂缓。

## 为什么

行程要在地图上看得见：每天走哪条路、点之间远不远。境外用 Google、境内用高德，是你的要求；选择依据是**目的地所在地区**。

## 范围

做：每日地图、全程分色路线、标记聚类、地点搜索与详情、一键导航、供应商抽象与降级。
待你拍板：3D 与地形（F33，建议不做）。
做（v0.5 K2）：高德（F28 国内部分）；代理（F34）只在 README 写明用环境变量走代理，不做界面。
后做：视口 POI 探索（F30，你 2026-10-22 拍板推到 v0.5 之后）。

## 用户故事

- 作为游客，我想在地图上看到当天的点和编号路线，顺序一眼能看懂。
- 作为游客，我想搜一个地点加进候选池，并看到它的评分和开放时间。
- 作为游客，我想一键用 Google 地图（境外）或高德（境内）打开某段路线导航。

## 验收场景

**S1 P0 · 每日地图显示全部点**
- 假设 某天有 4 个地点（含不在旧白名单里的）
- 那么 地图上 4 个编号标记按行程顺序连线，悬停显示名称和到达时间

**S2 P0 · 按地区选供应商**
- 假设 目的地是巴黎
- 那么 地图和地点服务走 Google；Key 缺失时降级为 OpenStreetMap 瓦片，页面不报错，仅在设置页提示「当前使用基础地图」

**S3 P1 · 全程分色路线（v0.2 已做）**
- 假设 我打开行程页的「全程地图」（工具栏下面可展开的卡片，标题写着地点数和总距离）
- 那么 每一天一种颜色，图例列出每天的距离；点图例可只看某一天，再点一下回到全部
- 并且 距离是「按顺序经过各点的直线距离累计」，页面上明说，不冒充实际步行 / 通勤距离（真实通勤时间随 Google 一起做）

**S4 P1 · 搜索并加入候选池**
- v0.2 先做**地点库内搜索**（见 M02 S5b）；下面的 Google 外部搜索随 Google 一起做，库外地点需要「待核实」数据模型（没有开放时间 / 闭馆日 / 停留时长）后才能排程。
- 假设 我在候选池页搜索「Pierre Hermé」
- 当 选择一个结果
- 那么 显示名称、地址、评分、开放时间（来源标注「Google」），点「加入候选池」后出现在候选列表，并标记来源为「用户添加」

**S5 P1 · 一键导航（v0.2 先做 Google，不需要 Key）**
- 假设 我点击某个地点下面的「从『上一站』导航」，或某一天顶部的「在 Google 地图中打开当天路线」
- 那么 新标签页打开 Google 地图路线：两点之间用公共交通，整天的路线按顺序串起来（步行）；只用核对过的坐标，不依赖名字能否被 Google 认出来
- 并且 一天的点超过 Google 链接上限（起点 + 9 个途经点 + 终点）时拆成「第 1 段 / 第 2 段」，相邻两段共用衔接点
- 并且 行程页能「导出 KML」：每天一个文件夹（编号标记 + 一条连线，颜色同全程地图），可导入 Google「我的地图」或 Google Earth
- 境内城市改走高德随 v0.5 一起做

**S6 P1 · 标记聚类（v0.2 已做）**
- 假设 全程地图上标记很密
- 那么 缩小时聚合成带数字的圆圈，放大后展开；点标记打开地点详情卡
- 注：用 leaflet.markercluster 1.5.3（Leaflet 官方组织维护，MIT，已固定版本）

**S7 P1 · 国内城市的地图走高德（v0.5 K2，见 M17）**
- 假设 目的地是北京或西安（`City.map_provider = amap`）
- 那么 行程页地图、全程地图、今天卡片都用高德 JS API 2.0 渲染：编号标记、分色折线、信息窗、聚类、点标记打开地点详情卡，行为与巴黎一致
- 并且 **坐标统一存 WGS-84**（地点库、行程、导出都是），只在调用高德（画图、搜索、路线、导航）时转成高德用的 GCJ-02，换算公式自己实现、不引入依赖；单元测试用已知点校验误差 ≤ 5 米
- 并且 没配 Key、Key 失效、脚本加载失败、配额用完：自动退回 OpenStreetMap 地图（直接用 WGS-84 画，位置是对的），页面提示「当前使用基础地图」，不报错
- 并且 **天气不走高德**：继续 Open-Meteo（你 2026-10-22 拍板；高德天气只有 3 天预报、个人认证每月 5000 次）
- 并且 高德**只做地图、搜索、路线，不做事实来源**：高德返回的开放时间 / 价格 / 评分不进地点库、不进排程

**S7 实现说明（K2 第 ① 批，2026-11-02）**
- 哪座城市用高德：`City.map_provider`（不写 = 中国的城市用高德，其余 OSM）；前端按**这一张地图里所有点的位置**判断（都在大陆范围内才走高德，否则 OpenStreetMap；混着巴黎和上海的路线退回基础地图）。
- 前端：`web/src/mapkit.ts`（加载官方脚本 `webapi.amap.com`，不引第三方包；WGS-84→GCJ-02；整页只问一次后端、算一次地图加载）、`web/src/components/amapDraw.ts`（编号标记、折线、悬停气泡、全程地图聚合 ≥13 级展开）。
- 后端：`app/maps/`（`coords.py` 坐标换算、`quota.py` 配额、`config.py` 读 `.env`）；`GET /map/config`、`GET /map/usage`。Web 服务 Key 不下发给前端。
- 验收场景：**M25**（境内行程没配 Key 时退回基础地图并写「当前使用基础地图（没配高德 Key）」；导航链接是高德，见 S7e）；有 Key 的真实画面见 K2 第 ① 批的前端检查。

**S7e P1 · 导航链接跟着目的地走（2026-11-02，你指出国内行程还写着「在 Google 地图里打开当天路线」）**
- 假设 一张地图 / 一天的点都在大陆范围内（上海、重庆、北京等）
- 那么 「当天」按钮是「在高德地图中查看当天地点」，链接是高德网页「多点标注」（`uri.amap.com/marker`，一条最多 10 个点，多了分段）；每个点的「从上一站导航」「导航」是高德网页导航（公共交通，`mode=bus`）；「附近餐厅」搜高德。网页链接不要 Key、不耗高德配额，坐标换成高德的 GCJ-02
- 并且 **高德网页链接只支持两点之间的路线（途经点只在驾车有效）**，所以当天按钮是「看当天所有地点」，不是连成一条步行路线；要某两点之间的路线用点对点的「导航」
- 并且 境外（巴黎等）完全不变，仍是 Google；一天里有境内也有境外的点时按城市分段，各用各的
- 并且 全程地图上的聚合圆圈点一下放大到刚好装下这一簇的点（高德版，和 Leaflet 版一致）

**S7b P1 · 门到门通勤时间（v0.5 K2，F16 的国内部分）**
- 假设 我打开国内行程的某一天，点这一天的「查看真实通勤时间」
- 那么 这一天相邻两个点之间显示步行 / 公交的**真实时间**（高德路径规划）：近的（排程估算为步行）查步行，远的查公交 / 地铁；点开能看到「步行 320 米 → 地铁 1 号线 → 步行 150 米」这类分段；取不到的那一段继续显示排程的估算，并写明「估算」
- 并且 **只有点了按钮才调高德**，打开行程不调；每一段算一次「基础 LBS」配额，到自留上限当月不再查，页面提示原因（「没配高德 Key，先用排程的估算」「本月查路线的次数用完，先用估算」「暂时没查到，先用估算」），不报错
- 并且 排程器**不在循环里调高德**（保持确定、离线、可测）：路线时间只用来显示和事后提醒「实际要 X 分钟，比排程估的多 Y 分钟」（差 ≥ 10 分钟才提醒）
- 并且 **高德返回的路线不缓存、不保存**（2026-11-03 取到服务协议原文：3.5、4.12.3、7.3 条不许存储 / 缓存服务数据，没有写缓存期限，要留存须向高德提工单）：只显示在当前页面上，刷新就没了，再看再查再计数；不进数据库、不进日志、不进导出 / 分享
- 并且 只有国内城市有这个按钮；巴黎等不出现
- 接口：`POST /commute`，请求 `{city, legs:[{from_lat, from_lng, to_lat, to_lng}]}`（最多 12 段，坐标 WGS-84），回 `{legs:[{minutes, mode, distance_m, steps[]} | null], reason?}`；高德只拿到坐标，不带行程里的任何其他信息

**S7c P1 · 高德配额保护：不让你被收费（v0.5 K2，2026-11-02 你要求「不要让我高德开始收费」）**
- 事实（高德开放平台定价页，2026-11-02 取到）：个人认证开发者每月免费额度——基础 LBS（路线规划、地理编码、逆地理编码、坐标转换、静态地图）15 万次；基础搜索（关键字 / 周边 / 输入提示）**5000 次**；地图图面初始化 150 万次；天气 5000 次（我们不用）。免费额度从认证日起算 **1 年**；额度用完后要自己买流量包才能继续，页面没写自动扣费；到期后怎么算以控制台为准。
- 那么 后端自己记账：按服务、按自然月统计调用次数（SQLite `map_usage` 表），**每类服务设「自留上限」，远低于免费额度**：搜索 2000 次（额度的 40%）、基础 LBS 50000 次（33%）、地图初始化 300000 次（20%）；到上限后这一类服务**当月不再调高德**，自动降级（路线退回直线估算并写明「估算」、搜索退回地点库内搜索、地图退回 OpenStreetMap），页面不报错
- 并且 到自留上限的 80% 在「模型用量」页提示；`GET /map/usage` 给出每类服务本月已用 / 自留上限 / 免费额度
- 并且 **只对我们代码里的调用记账**；你在高德控制台里看到的才是官方数字，认证满 1 年前请自己看一眼「流量分析 → 配额管理」
- 并且 库外搜索只在用户主动点「搜索」时调用，不在输入时联想；**高德服务协议不许缓存服务数据（2026-11-03 核对，见 S7b），所以不做缓存**，同一个词再搜就再调、再计数
- 并且 控制台里不要点「购买流量包」或开通后付费；这是你那边的开关，代码这边不会替你买

**S7d P1 · 库外地点与住宿地址（v0.5 K2 第②批）**
- 假设 我在国内城市（重庆）的候选池里搜「磁器口」，地点库里没有
- 那么 提示「地点库里没有找到」，下面多一个按钮「在高德里搜「磁器口」」；**只有点了才调高德**（输入时的联想只搜地点库，不耗搜索配额）
- 并且 点了以后列出最多 5 条：名字、地址、类型；每条有「加入并标为必去」，和地点库里搜到的地点一样直接加进候选池、直接排进行程，**不再先进「待核实」**
- 并且 加进来的地点成为这座城市地点库里的一个点（存在 `data/generated/user-places/{城市}.json`，不进仓库；城市数据重建也不丢）：开放数据草稿档，来源写「高德」；名字、地址、坐标（WGS-84）来自高德，**这是你自己点「加入」选定的地点**，不存高德的地点编号和其他返回内容（编号由名字 + 坐标算出，同一个点只加一次）；类别按高德的分类换算，停留时长按类别给默认值（景点 / 博物馆 90 分钟，公园 / 餐饮 / 购物 60 分钟）；**没有开放时间、闭馆日、价格**，高德返回的任何经营信息都不收；价格在预算里算「待补」
- 并且 因为营业时间没核对，**这个点出现的每个地方旁边都标「营业时间没核对，出发前请自己查」**：候选池里这一行、行程里这一项的备注
- 并且 同一个高德地点只会加一次（按名字 + 坐标）；坐标落在城市范围之外的不收，提示原因
- 并且 没配 Key、本月搜索到自留上限、网络出错 → 只提示原因（「没配高德 Key」「本月搜索次数用完，先用地点库」「暂时连不上高德」），什么都不加；非国内城市（巴黎等）不出现这个按钮
- 假设 我给国内城市的酒店填了地址
- 那么 先用高德地理编码定位（算「路线、地理编码」一类）；没配 Key / 到上限 / 定位不到，再退回 OpenStreetMap；仍然定位不到，用所在区中心，写明「按 X 区中心估算」；巴黎等非国内城市仍用 OpenStreetMap
- 并且 高德返回的是 GCJ-02 坐标，存下来前换成 WGS-84（和库里一致）；地址只发给高德这一个服务，不写日志
- 假设 我在新建页目的地写「重庆」
- 那么 和「重庆市」一样认出来（中文城市名带不带「市」都行）
- 验收场景：**M26**（国内城市候选池里搜库外地点：按钮、结果、加入、行程里有这个点和「营业时间没核对」的备注；没 Key 时的提示）、**M27**（目的地写「重庆」认得出是重庆市）

**S7b 验收场景（K2 第③批）**：**M28**（国内行程的一天：点「查看真实通勤时间」，相邻两点之间出现真实时间和分段；没 Key 时给原因、仍显示估算）、**M29**（巴黎的行程每天没有这个按钮）

## 数据与接口

- `MapProvider`：`geocode / search_places / place_details / directions`；实现 `GoogleProvider`、`AmapProvider`、`OsmProvider`。
- 接口：`GET /places/search?q=&region=`（只搜地点库）、`GET /places/lookup?q=&city=`（点了才调，高德搜库外地点，S7d）、`POST /places/custom`（把高德搜到的点加进这座城市的地点库，S7d）、`GET /trips/{id}/route?day=`、`GET /map/config`（返回当前应使用的前端地图 SDK 与 Key 的公开部分）。
- Key 只在 `.env`：`AMAP_WEB_KEY`（后端调用 Web 服务）、`AMAP_JS_KEY` 和 `AMAP_JS_SECRET`（前端 JS API 2.0，必须配安全密钥）；浏览器端 Key 要在高德控制台限制来源域名。`GET /map/config` 在运行时把前端要用的部分下发，**不写进仓库**。本机自用直接下发；将来对外部署要换成代理转发（`serviceHost`），不在前端暴露安全密钥。
- 前端引入高德 JS：用官方加载器 `@amap/amap-jsapi-loader` 或直接加载官方脚本二选一，K2 开始前先审（包是否真实、版本固定、许可证）再用。
- 后端 `AmapClient`（`app/maps/amap.py`）：地理编码、关键字搜索、路径规划（步行 / 公交）、配额计数；`MapProvider` 接口见上，K2 一起落地。

## 验收方式

- **自动化**：供应商选择函数（按地区）；假供应商下的搜索 / 路线；Key 缺失降级。
- **前端**：你按 S1、S3 看地图；Playwright 断言标记数量等于当天点数、折线存在。
- **成本**：每次生成统计地图 API 调用次数，设日预算上限，超限降级。
