# M10 随行工具

> 版本：v0.3（天气、打包清单、待办、笔记）→ v0.4（文件附件）
> 功能：F57 F58 F59 F60 F61 F62 · 来源：TREK（行李、待办、笔记、附件、天气）+ TripStar（天气）
> **现状（2026-10-28）**：✅ 已做完：天气（预报 + 去年同期、雨天室内备选）、行李清单、待办、每条安排的备注、文件附件。

## 为什么

行程之外，出行还有一堆琐事：天气、带什么、办什么、文件放哪。放在同一个行程里，出国时一个页面都能找到。

## 范围

做：天气预报（含降雨提示联动行程）、行李清单（按目的地 / 季节生成模板）、待办、每日笔记、文件 / 票据附件。
待你拍板：行李重量与分袋（F62）。
汇率换算见 M09。

## 验收场景

**S1 P1 · 天气与行程联动**（v0.3 批次 C）
- **S1a 每天的天气就在这一天旁边**：每天标题那一行（「第 N 天 · 日期 · 主题」）右侧有一枚天气：图标、天气文字、最高 / 最低温、降雨概率；手机上换行显示在标题下面。**不再有单独的天气卡**。数据来自 Open-Meteo，后端缓存 3 小时；日程列表上方有一行小字说明数据来源。
- **S1b 太远就看去年同期**：日期在今天起 15 天内用预报；更远的日期用**去年同一天**的实际天气，天气旁标「去年同期」，只给天气和温度、不给降雨概率，也**不触发**下面的雨天联动（那不是预报，不能据此改行程）。
- **S1c 雨天联动**：某天预报降雨概率 ≥ 60%，当天标题下出现「🌧 预报降雨概率 80%」提示，行程里的**室外点**打上「室外 · 可能淋雨」小标签；提示里有「编辑行程，换成室内备选」按钮。
- **S1d 换成室内备选**：进入编辑后，雨天里的室外点的「换一个」变成「换成室内备选」，备选只来自**室内**地点（沿用 M04 的换一个：同主题 / 同区域 / 当天开门 / 行程里还没有）；换完后重新排程。半室外的点（如花园 + 内部参观）只提示「可能淋雨」，不强推换。
- **S1e 接口失败不报错**：天气接口失败 / 超时（5 秒）/ 返回异常时，每天的天气都不显示，也没有任何红色提示；有缓存时用缓存。重新打开页面会重试。
- **S1g 分享页也带天气**：公开分享页每天标题行同样有天气（预报 / 去年同期）、雨天提示和室外标签（只读：没有「编辑行程，换成室内备选」按钮）；接口失败时不显示、不报错。分享接口 `GET /share/{token}` 增加 `weather` 字段（不含行程号和需求原文这一约束不变）。
- **S1h PDF / 导出也带天气**：PDF、HTML、Markdown 导出里每一天的标题下有一行天气（天气文字 · 最高 / 最低温 · 降雨概率；去年同期的标「去年同期，仅作参考」）；预报降雨概率 ≥ 60% 时补一句「预报降雨概率 N%，室外点：…，建议备选室内」。取不到天气时这一行整体省略，导出照常成功。
- **S1f 地点的室内 / 室外是策展数据**：地点库每个地点有 `setting`（`indoor` / `outdoor` / `mixed`），随地点库一起核对，不由 LLM 判断。

**S2 P1 · 行李清单**（v0.3 批次 E）
- **S2a 按行程生成**：行程页有「随行」卡片，「行李」页签里点「按行程生成清单」：按**出行季节 / 气温**（有天气预报用预报，没有用月份的常年气温估算）、**行程天数**、**出行人**（有 12 岁以下的加儿童用品，4 岁以下再加婴幼儿用品）、**行程内容**（有演出 / 高级餐厅加体面的衣服；摄影主题加相机和存储卡）生成分类清单：证件 / 衣物 / 电子 / 药品 / 洗护 / 其他（/ 儿童）。算法生成，不用模型。
- **S2b 事实留痕，只有「官方规定」才在页面上给来源**：护照有效期（申根区：离境后 3 个月以上、签发不满 10 年）、插头插座（法国 230V / 50Hz、C / E 型圆脚）的依据仍记在 `data/companion/packing.json` 里（来源 + 核对日期，供自己核对），但**页面上这两条不显示「来源 ↗」**——它们只是带什么的提醒；只有涉及**官方规定**的条目才在条目旁给官方来源链接，由数据里的 `show_source` 控制（默认不显示）：现在只有「签证 / 入境材料」这一条（来源 france-visas.gouv.fr，是否需要签证、要哪些材料以官方为准，不替官方下结论）；有人享受年龄 / 居留 / 学生优惠时，加「证明年龄 / 居留身份 / 学生身份的证件」（和预算联动：现场会查）。其余是经验性建议，标「建议」。
- **S2c 可勾、可增删、有进度**：每项可勾选「已带」、改名、删除、自己加；顶部进度「已带 12/30」，每个分类也有小计。清单是你自己的状态：**不产生行程版本**，复制行程时一起复制，删除行程时一起删除。
- **S2d 重新生成不覆盖**：再点「补充推荐项」只会补上还没有的推荐项（按推荐项的编号去重），你勾过的、改过的、自己加的都不动；你删掉的推荐项不会自动回来，除非点「恢复推荐项」。
- **S2e 分享页默认不显示，可以勾选分享**：分享弹窗里有「一起分享：行李清单 / 待办 / 行程备注」三个勾选，**默认都不勾**；勾了的，朋友在分享页才看得到（只读，看不到修改入口），可随时改勾选、立刻生效，链接不变（M08 S5b）。

**S3 P1 · 待办**
- **S3a** 我添加待办「办申根签证」并设截止日期（可不设）；可勾完成（划线）、改、删。
- **S3b 临近截止红色提示**：截止日已过 = 红色「已过期 N 天」；今天或 3 天内 = 红色「还有 N 天 / 今天截止」；更远 = 灰色日期；已完成不再提醒。顶部汇总「N 项待办，M 项快到期 / 已过期」。
- **S3c 推荐待办**：点「看推荐待办」列出可以一键加入的建议，日期按出发日倒推：核对护照有效期（−60 天）、核对入境要求 / 办签证（−45 天，以 france-visas.gouv.fr 为准）、订机票（−60 天）、订住宿（−45 天）、买旅行保险（−14 天）、换欧元 / 办外币卡（−10 天）、开通漫游 / 买电话卡（−7 天）、保存离线行程和地图（−3 天）、网上值机（−1 天）。天数是**建议**，不是官方规定，页面标明。**购票清单里有明确提前天数的景点**，再加一条「订『卢浮宫』门票」，截止日就是「建议最晚订票日」（M06 S3）。已经加过的不重复；日期已经过去的，截止日按今天并标「已临近，尽快」。
- **S3d** 待办不产生行程版本；复制 / 删除行程时跟着走；分享页默认不显示，分享弹窗里勾了「待办」才显示（只读）。

**S4 P1 · 行程备注（每一条行程安排各自的笔记）**
- **S4a 针对某一条安排写备注**：每天展开后，**每一条行程安排**（景点、午餐、住宿到达……）右边有「📝 备注」按钮；点开出现输入框（最多 2000 字），**离开输入框自动保存**并提示「已保存」；清空 = 删除这条备注。有备注的安排，备注文字直接显示在这一条下面（不用点开）。**不再有「整天一条」的笔记框**；以前写过的整天笔记不丢，保留在当天标题下一行小字里，可以改、可以清空。
- **S4b 备注跟着安排走**：来自地点库的点（有 `place_id`），备注按地点记，**拖到别的一天、换时间都跟着**；没有地点的安排（午餐占位等）按「日期 + 名称」记。删掉这条安排后备注不显示，把它加回来又出现。
- **S4c** 备注出现在**行程页**和 **PDF / HTML / Markdown 导出**里对应那一条安排下面；**分享页默认不显示**，分享弹窗里勾了「行程备注」才显示（只读）。
- **S4d** 平移日期时，没有地点的安排的备注、整天笔记跟着换成新日期；按地点记的备注不受影响。复制 / 删除行程时跟着走。

**S5 P1 · 文件附件（v0.4 批次 I；你已拍板：存本地目录 + 数据库记录，不引入新依赖）**
- **S5a 上传**：行程页「随行」卡多一个「文件」页签；点「上传」选文件（或拖进来），列表里出现：文件名、类型图标、大小、上传时间、挂在哪（整个行程 / 某个地点 / 某一天 / 某条预订）。只收 **pdf / png / jpg（jpeg）**，单个 ≤ 10MB，一个行程最多 50 个文件。类型按**文件内容的开头字节**判断，不信扩展名和浏览器报的类型；不合格时弹窗（`ErrorPopup`）写清原因：「只支持 PDF / PNG / JPG」「文件超过 10MB（当前 x.x MB）」「这个行程的文件已达 50 个上限」「文件内容和扩展名对不上」。
- **S5b 挂靠**：上传时可选「挂到…」：整个行程（默认）/ 某个地点 / 某一天 / 某条预订；之后可在列表里改。预订记录那一行、地点详情卡、每天标题处各有一个回形针图标 + 数量，点开直接看挂在那里的文件。
- **S5c 预览 / 下载**：图片点开在应用内弹窗预览；PDF 点开在新标签页打开（`Content-Disposition: inline`）；「下载」给回原文件名。后端响应头一律 `X-Content-Type-Options: nosniff`，并带 `Content-Security-Policy: sandbox`（附件里的脚本无论如何不会执行）。
- **S5d 安全**：文件名清洗（去路径、控制字符、`..`，保留中文，长度 ≤ 100）；磁盘上用随机 id 命名，**不用用户给的文件名**（`data/attachments/<行程id>/<附件id>.<扩展名>`），所以不可能目录穿越；不解析、不执行文件内容；应用启动时不扫描附件。
- **S5e 回收站**：删除先进「回收站」（列表底部「回收站 N」展开，可「恢复」或「彻底删除」）；回收站里 30 天后自动清理；永久删除行程时附件文件一并删除；复制行程**不**复制附件（那是你的私人文件）；平移日期时挂在某一天的文件跟着换成新日期。
- **S5f 不外露**：公开分享页、PDF、长图、Markdown 导出**都不含**附件（预订截图含确认码，和确认码一样不外露）；分享弹窗里不提供「一起分享文件」。
- **S5g 离线**：行程页读过的附件列表可离线看；文件本身不进离线缓存（体积大且含个人信息）。
- **S5h 挂靠校验**：地点 / 预订要是地点库里的地点，某一天要是这份行程里的日期，否则提示「挂靠的对象不存在」；整个行程不需要对象。
- **S5i 入口**：「随行」卡的「文件」页签（总列表，可按挂靠筛选）；每天标题、预订记录那一行、地点详情卡（在行程页里打开时）有回形针 + 数量，点开跳到「文件」页签并筛选到那一项。
- **S5j 验收记录**见 `tests/test_attachments.py`（类型 / 大小 / 数量 / 文件名 / 路径穿越 / 响应头 / 回收站 / 不外露 / 复制不带 / 平移）和 `tests/e2e/test_v04_attachments.py`。

## 数据与接口

- 实体：`PackingItem`、`Todo`、`Note`、`Attachment`（见 [03](../03-data-model.md)）。v0.3 的三张表：`packing_items(id, plan_id, key, category, text, packed, position)`、`todos(id, plan_id, key, text, due, done)`、`day_notes(plan_id, date, text)`——v0.3 起这张表的 `date` 列改存「备注对象」`ref`（地点用 `place_id`；没有地点的安排用 `日期|名称`；以前的整天笔记用 `day|日期`），主键 `(plan_id, ref)`；都是用户自己的状态，不进行程版本。
- 行李模板：`data/companion/packing.json`（分类、条件、数量规则；带事实的条目有 `source_url` + `checked_at`）；`app/companion.py`（纯函数：生成清单、推荐待办、待办紧急度）。
- 接口：`GET /plans/{id}/packing`、`POST /plans/{id}/packing/generate`、`POST /plans/{id}/packing`、`PATCH / DELETE /plans/{id}/packing/{item_id}`、`POST /plans/{id}/packing/restore`；`GET /plans/{id}/todos`（含紧急度和推荐待办）、`POST / PATCH / DELETE /plans/{id}/todos[/{todo_id}]`；`GET /plans/{id}/notes`（`{notes: {ref: 文本}}`）、`PUT /plans/{id}/notes`（body `{ref, text}`）。
- 前端：`CompanionCard`（行程页的「随行」卡，行李 / 待办两个页签）、每条行程安排上的备注按钮和备注框（`ItemNote`）。
- 天气：公开天气接口（Open-Meteo，无需 Key），缓存 3h。预报接口 `api.open-meteo.com/v1/forecast`（今天起 15 天内），历史接口 `archive-api.open-meteo.com/v1/archive`（去年同期）；每日取 weather_code / 最高温 / 最低温 / 降雨概率 / 降雨量；坐标取目的地城市中心。
- 后端：`app/weather.py`（`WeatherService`：取数、缓存、降级，HTTP 客户端可注入便于测试）；`GET /plans/{id}/weather` → `{available, days:[{date, source: forecast|history, label, t_max, t_min, rain_prob, rain_mm, rainy, outdoor_places:[…]}]}`；`POST /plans/{id}/alternatives` 增加 `indoor_only`。
- 前端：每天标题行里的天气（`WeatherChip`）、雨天提示 + 室外标签、编辑时的「换成室内备选」。
- 附件：`app/attachments.py`（校验：类型按魔数、大小、文件名清洗；存取；回收站）；表 `attachments(id, plan_id, name, kind, size, target_kind, target_ref, uploaded_at, deleted_at)`（`target_kind` ∈ plan / place / day / reservation；`target_ref` 是地点 id / 日期 / 预订 key）；文件在 `ATP_DATA_DIR/attachments/<行程id>/<附件id>.<扩展名>`（`ATP_DATA_DIR` 默认 `data/plans` 同级，测试用独立目录）。接口：`GET /plans/{id}/attachments`（返回 `{attachments, trash, limits}`）、`POST /plans/{id}/attachments?name=文件名&target_kind=&target_ref=`（**请求体就是文件本身的字节**，不用 multipart，所以不需要新装依赖；服务端边读边数，超过 10MB 立刻停止；声明的 `Content-Length` 超限时连读都不读）、`GET /plans/{id}/attachments/{aid}/file`、`PATCH /plans/{id}/attachments/{aid}`（改挂靠 / 恢复）、`DELETE /plans/{id}/attachments/{aid}`（进回收站；`?permanent=1` 彻底删）。前端：`web/src/components/Attachments.tsx`。

## 验收方式

- **自动化**：行李清单生成规则（季节 / 天数 / 儿童 / 演出 / 摄影 / 优惠证件 / 全员长居欧洲时不带转换插头）、按编号去重不覆盖、恢复推荐项、数据里每条事实带来源、待办紧急度（过期 / 今天 / 3 天内）、推荐待办的日期倒推与购票截止日、笔记的保存 / 清空 / 长度限制 / 平移日期、导出带笔记、分享页不带清单 / 待办 / 笔记、复制 / 删除跟着走；天气——预报 / 去年同期的选择、weather_code 翻译、雨天阈值（≥60% 才算，历史不算）、缓存、接口失败降级（不报错、不显示）、室外点的标出、`indoor_only` 备选只含室内地点；地点库每个地点都有 `setting`。附件（v0.4）——类型按魔数判断（改扩展名的 exe / html 被拒）、大小与数量上限、文件名清洗与路径穿越、挂靠、回收站（恢复 / 30 天清理 / 永久删除）、响应头（nosniff / sandbox）、分享 / 导出不含附件、复制不带附件、平移日期跟着换。
- **前端**：你按 S1–S5 点。
