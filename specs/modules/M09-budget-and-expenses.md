# M09 预算与花费

> 版本：v0.3（预算面板）→ v0.4（多币种、CSV）→ v0.7（多人分摊）
> 功能：F53 F54 F55 F56 · 来源：TripStar（预算面板）+ TREK（记账、分摊、汇率）
> **现状（2026-10-28）**：✅ 已做完（v0.3 批次 D）：预算面板、出行人逐位算优惠、结算货币与并列货币、超预算自动换便宜的。多币种录入、CSV、分摊（v1.x）后做。

## 为什么

出发前想知道大概要花多少，出发后想知道花了多少、和朋友怎么分。

## 范围

做：行程预算估算（门票 / 餐饮 / 交通 / 住宿）、人均与总计、实际花费记录、多人分摊、汇率换算（EUR→CNY）。
不做：支付、银行同步。

## 验收场景

**S1 P1 · 预算估算**（v0.3 批次 D；2026-10-14 按你的反馈修订：出行人身份、结算货币、淡旺季）
- **S1a 预算卡**：行程页有「预算」卡片（可收起）：门票 / 餐饮 / 交通 / 住宿四类，每类一行、带占比横条、标来源；底部是总计和人均（总计 ÷ 人数）。金额用你选的**结算货币**为主，旁边并列另一种货币（主为人民币 → 并列欧元；主为欧元 → 并列人民币），按汇率换算。
- **S1b 门票按每个人算**：用出行人的年龄 / 长居身份 / 是否学生，对行程里每个收费景点逐人取**最低的适用价**（成人价、欧盟居民价、儿童 / 青年价、免费、学生价），并按**这个景点被排在哪一天**取对应月份的价格（淡旺季）。
  - 价格是策展数据：`price_eur`（成人全价、非欧盟居民、线上价）、`price_periods`（分月份价格，如凡尔赛 4–10 月 €35 / 11–3 月 €25）、`concessions`（欧盟居民价、年龄段价、学生价），每条都带官方来源网址和核对日期。
  - 优惠的口径（和官网一致）：`any` = 所有人；`resident_eu` = 长居欧盟 / 欧洲经济区（官网写「EEA 居民」「欧盟居民」）；`resident_fr` = 长居法国（官网写「欧盟公民和长居法国的非欧洲居民」）。长居法国同时满足 `resident_eu`；长居其他欧盟国家只满足 `resident_eu`。出行人默认按中国游客，不单独问国籍。
  - 没核对过优惠规则的景点：一律按「成人全价」算，卡片里写「N 个景点优惠规则未核对，按全价」并点名；某个月份官网没写价格时按最近的已核对价并注明。
  - 卡片里写清已经计入了哪些优惠（如「2 位 17 岁以下免票，共省 €xx」）。
  - 没有价格的景点仍列「待补」，不算 0；公共开放空间、餐饮 / 购物点不收门票，不算待补。
- **S1c 其他三类**
  - 餐饮：**估算**——按预算档位「每人每天参考值」× 天数；4 岁以下不计、12 岁以下按一半（都是估算规则，页面标「估算」）；可改成自己的每人每天金额。
  - 交通：官方 2026 年票价。4 岁以下免费、4–9 岁单程票 €1.30（官方儿童票）、10 岁以上 €2.55；10 岁以上的人单程票和 Paris Visite 通票取便宜的；4–9 岁儿童单程票和儿童通票（半价：€15.30 / €22.70 / €31.90 / €39.00）取便宜的。通票只有「全区」一种（官方 2026 年价目页没有区域 1–3 的版本，2026-10-14 核对）。不含机场往返和 Navigo Easy 卡工本费。
  - 住宿：你在「住宿」里填的每晚价格 × 晚数，一间房总价；没填的晚数「待补」。
- **S1d 结算货币**：卡片里可随时切换人民币 / 欧元；切换后保存（每份行程各记各的），旁边始终并列另一种货币。
- **S1e 汇率**：Frankfurter（欧洲央行参考汇率），缓存 24 小时；卡片底部写「汇率 1 欧元 = 7.489 元（欧洲央行参考汇率，2026-10-13）」；拿不到时用上一次成功的值并标「旧数据」；一次都没成功过时只显示欧元并说明。
- **S1f 导出**：PDF / HTML / Markdown 带「费用估算」一节：按结算货币为主、并列另一种，含各类来源、待补、优惠说明、汇率日期、预算上限情况。
- **S1g 分享页不显示预算**。
- **S1h 出行人可以事后修改**：预算卡里能改人数、每个人的年龄 / 长居 / 学生、结算货币、预算上限、餐饮每人每天；保存后立刻重算，**不产生行程版本**，也**不会自动重排行程**（要让新预算影响行程，看 S2d）。

**S2 P1 · 预算偏差提示**
- **S2a 预算上限**：开头可选填（见 M01 S4b），事后也能在卡片里改；单位是结算货币。
- **S2b 超出时提示**：估算总计超过上限时，卡片顶部出现「估算 ¥x，超出预算 ¥y」，并列出**最多 3 条可替换的更低价项**（同主题 / 同区域 / 当天开门，沿用「换一个」的规则；按出行人身份算省多少）。每条旁边有「编辑行程，换成它」：点了就进入编辑并把这一换应用上去——还没保存，可以直接放弃或继续改。没有更便宜的候选时写「没有更便宜的同主题替代」。
- **S2c 没超出**：显示「在预算内，还剩 ¥z」；有待补项时注明「实际可能更高」。
- **S2d 开头填了预算上限就直接考虑进去**：见 M01 S4b；生成时自动换更便宜的，并在行程页留痕。

**S3 P2 · 记一笔花费（v0.4）**
- 假设 我在第 2 天记一笔「午餐 €48，由 A 付」
- 那么 花费列表新增，合计更新，汇率换算为人民币并标注汇率日期

**S4 P2 · 分摊结算（v0.7，依赖多人）**
- 假设 3 人行程里有多笔不同付款人的花费
- 那么 「结算」页显示谁该给谁多少，且总和为 0

## 数据与接口

- v0.3 的实体：出行人 `Traveler{age, residence: none|fr|eu, student}`（需求 `TravelRequest.travelers / budget_cap / currency` 带初始值，生成时用）；预算设置 `budget_settings(plan_id, party_json, currency, cap_amount, meal_eur_per_day)`（每份行程一行，用户状态，不进行程版本，复制时带上；创建行程时由需求写入，之后以它为准）；汇率缓存 `fx_rates(base, quote, rate, rate_date, fetched_at)`（保存最后一次成功值，重启后失败降级也能用）。
- v0.4 之后的实体：`Expense{id, trip_id, day, amount, currency, paid_by, split_among[], category}`。
- 汇率：Frankfurter（`api.frankfurter.dev/v1/latest?base=EUR&symbols=CNY`），缓存 24h，失败时用最后一次值并标注日期。
- 策展数据：`data/budget/paris.json`——交通票价（单程票及儿童票、Paris Visite 1 / 2 / 3 / 5 天，各带官方来源网址和核对日期）、餐饮每日参考值（标 `kind: estimate`）；景点价格和优惠在 `data/places/paris.json` 的 `price_eur / price_periods / concessions`。
- 后端：`app/fx.py`（汇率，任意两种货币经欧元换算）、`app/budget.py`（纯函数：逐人逐景点算价、交通取便宜、超预算建议、`fit_to_budget` 生成后按预算自动换）；接口 `GET /plans/{id}/budget?version=n`、`PUT /plans/{id}/budget-settings`（body：`travelers[]`、`currency`、`cap`、`meal_eur_per_day`，传了哪个改哪个）。
- 前端：`BudgetCard`（行程页）。

## 验收方式

- **自动化**：逐人逐景点取最低适用价（成人 / 欧盟居民 / 儿童 / 青年 / 学生 / 免费，各景点的规则）、按景点所在日期取淡旺季价、未核对优惠按全价并点名、优惠口径（`any / resident_eu / resident_fr`）、门票求和与「待补」、餐饮档位与儿童折算、交通（儿童票、取便宜含 6 天以上）、住宿晚数与未填价格、结算货币互换与并列、汇率缓存 / 降级 / 旧数据标注、超预算建议只给更低价的同主题候选、生成时按预算自动换（不动锁定 / 必去的点，换不动写明还超多少，拿不到汇率时降级）、设置接口校验、导出带费用一节、分享页不带预算；（v0.7）分摊结算守恒（属性测试：净额之和为 0）。
- **前端**：你按 M01 S4b、M09 S1、S2 点（S3 在 v0.4）。
