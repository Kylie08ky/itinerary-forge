# M08 交付与导出

> 版本：v0.1（PDF 基础、Markdown / HTML）→ v0.2（PDF 完整、ICS、分享页）→ v0.3（长图）→ v0.5（GPX / KML）
> 功能：F47 F48 F49 F50 F51 F52 · 来源：TREK（PDF、ICS、GPX、分享）+ TripStar（图片导出）

## 为什么

行程最终要被「用起来」：打印、发给朋友、导进手机日历、出国时在手机上看。交付形式要多，而且每一种都要可读。

## 范围

做：PDF、Markdown / HTML、ICS、长图、公开只读分享。
后做：GPX / KML。

## 用户故事

- 作为游客，我想下载一份排版好的 PDF，里面有路线图和预约清单。
- 作为游客，我想把行程导进手机日历，到点提醒。
- 作为游客，我想发一个链接给没账号的朋友，让 TA 只读查看。

## 验收场景

**S1 P0 · PDF 基础**
- 假设 我在行程页点「下载 PDF」
- 那么 得到 PDF：每天一张表（时间、安排、时长、交通、备注）、预约清单（带官网链接）、风险提醒；中文显示正常

**S2 P1 · PDF 封面统计与路线图（v0.2 已做；多城市见 [11](../11-multi-city.md) M22：每座城市一张路线图）**
- 假设 同上
- 那么 第一页是封面：天数、地点数、直线距离累计、门票合计（仅地点库里有票价的点，不含餐饮和交通），下面是全程分色路线图和图例（每天的颜色、距离、经过的地点）；每天从新的一页开始，工具栏的「每天一页」勾掉后各天紧接着排
- 并且 ~~路线图是自绘的示意图（不含街道底图）~~ **2026-11-04 起带街道底图**，见 S2c；底图拿不到时才退回自绘的示意图
- 注：「预算」目前只有门票合计；餐饮、交通费用随 v0.3 预算面板一起做

**S2c P1 · 导出里的路线图带街道底图（2026-11-04，场景 M32）**
- 假设 导出 PDF / 长图 / HTML / 分享页打印（单城市一张、多城市每座城市一张）
- 那么 路线图下面是街道底图（OpenStreetMap 标准瓦片，国内外都是），每天一种颜色的线和圆点（里面是当天第几站）画在上面，右下角写「© OpenStreetMap contributors」
- 并且 瓦片在导出时下载并**直接嵌进文件**（离线打开也有图）；下载过的存在本机 `data/tile-cache/`，不重复下；一张图最多十几块，最多 2 个并发、带可识别的 User-Agent（OSM 瓦片使用政策）
- 并且 **不用高德的地图**：高德的服务协议不许把它的内容存进文件（M05 S7b 同一条）。库里的坐标是 WGS-84，和 OSM 瓦片一致，不用换算
- 并且 任何一块瓦片下不到（离线、被拦）或点分得太开放不进一张图：整张退回自绘的示意图，导出照常出得来
- 并且 图下面的说明写「线是按顺序连的直线、不是实际路线」

**S2b P1 · 导出里每个景点配图和简介、多城市文件名（规格 11 第 ⑥ 批，2026-11-02）**
- 假设 导出 PDF / 长图 / HTML（单城市、多城市一样）
- 那么 每个有核对过的实拍图的景点，在「安排」栏左边有一张缩略图，标题下面有一句简介（来自中文维基百科摘要，不是模型写的）；图和简介下面有一行小字署名：图片作者、授权、来源（Wikimedia Commons），简介来源（中文维基百科、CC BY-SA 4.0）。这些图片和简介就是地点卡 / 行程页上用的那一份（M02 S7b）。
- 并且 没有核对过图片的景点**不配图**（不拿别处的图凑）；官网、地址、参观重点只在有策展数据的地点出现——现建的城市没有核对过的，不写（规格 10 的硬规则），行程里已有「以官网为准」的提醒
- 并且 PDF / 长图里的图片直接嵌进文件（离线打开也有图）；浏览器里直接打开 HTML 时用本机的图片地址
- 并且 **文件名**：单城市照旧（行程号-vN）；多城市按行程里的顺序写上所有目的地，如「上海市-重庆市-20261101-9cd41c-v1.pdf」；PDF、长图、日历、KML 都一样，网页下载时也用这个名字

**S3 P1 · PDF 里的质检提示（v0.2 已做）**
- 假设 行程含未处理的 error
- 那么 封面有红色的「含 N 个未处理问题」提示；没有 error 时不出现

**S4 P1 · ICS 日历（v0.2 已做）**
- 假设 我点工具栏的「导出日历」
- 那么 下载 `.ics`；导入手机日历后，行程里每个条目（含午餐 / 晚餐占位）是一个事件：标题、地点（地点库里的点带地址和坐标）、时长、交通和备注；时间按巴黎时区，文件里带时区定义，不会错位
- 并且 每个事件开始前 30 分钟提醒；必须提前线上购票的点，描述里有醒目的「必须提前线上购票」，并多一个「前一天」的「需预订」提醒

**S5 P1 · 公开只读分享（v0.2 已做）**
- 假设 我点工具栏的「分享」——**弹出窗口**（不是页面里某个角落的面板，不管页面滚到哪都在当前画面里）→「生成分享链接」
- 那么 得到一个 `/s/随机令牌` 链接（令牌 ≥ 32 位）；一个行程同一时间只有一个有效链接，重复点会得到同一个
- 当 没有账号的朋友打开
- 那么 看到只读页：时间轴、全程地图、购票清单、风险提醒、地点详情卡、导航链接；没有编辑、版本、分享、下载入口，页面里也没有行程号和需求原文；看到的始终是你保存的最新版本
- 当 我点「关闭链接」
- 那么 朋友刷新后显示「链接已失效」（HTTP 410）；以后重新生成会得到新的令牌，老链接不会复活；不存在的令牌显示「没有这个分享链接」（404）

**S5b P1 · 分享时自己选一起分享什么（v0.3）**
- 假设 我打开「分享」弹窗（链接已生成）
- 那么 链接下面有「一起分享」三个勾选：**行李清单、待办、行程备注**，**默认都不勾**（行程本身、地图、购票清单、风险提醒、天气照旧）；改勾选立刻保存，**链接不变**，朋友刷新就看到新内容
- 当 勾了「行李清单」/「待办」/「行程备注」
- 那么 分享页多出对应的只读内容：清单按分类列出、标出哪些已带（不能勾选）；待办列出文字、截止日和是否完成；备注显示在对应那一条安排下面。接口 `GET /share/{token}` 只在勾了的情况下才返回 `packing` / `todos` / `notes`，没勾的字段**根本不在响应里**（不是前端藏起来）；响应里带 `shared`（勾了哪些），页面据此显示
- 并且 预算、出行人年龄、预订确认码、住宿**不提供分享选项**，分享页永远没有
- 接口：`GET /plans/{id}/share` 返回 `options`；`PUT /plans/{id}/share/options`（body `{packing, todos, notes}`）；没有有效链接时改选项返回 409；关闭链接再生成新链接，选项回到默认（全不勾）

**S6 P2 · 长图导出（v0.3 批次 F）**
- 假设 我点行程页「更多」里的「导出长图」
- 那么 按钮变成「生成中…」，生成好自动下载一张 PNG：竖向一整张，封面（城市、日期、天数 / 地点 / 公里统计）+ 全程路线图 + 每一天的天气和时间轴（时间、地点、时长、交通、官网购票提示），宽 760 CSS 像素、2 倍清晰度（太高时自动降到 1 倍，保证单边不超过 16000 像素，微信能发）；适合发朋友圈 / 微信
- 并且 **长图是拿去发给别人看的，所以不含**：预算、出行人年龄、预订确认码、你写的备注、住宿（和公开分享页的原则一致）；天气、路线图、购票提示照常
- 并且 和 PDF 一样：同一份内容再次导出直接取缓存；失败时弹出错误弹窗（不是新开空白标签页）；历史版本也能导（`?version=n`）
- 接口：`GET /plans/{id}/itinerary.png?version=n`；用 Playwright 截图（和 PDF 同一套，不引入新依赖）；页面字体同 PDF

**S6b P1 · 下载 PDF 要快、要有反应（v0.3）**
- 假设 我点「下载 PDF」
- 那么 按钮立刻变成「生成中…」（不可重复点），生成好自动开始下载，按钮恢复；生成失败时弹出错误弹窗（不是新开一个空白标签页）
- 并且 同一份内容（同一版本、同样的天气 / 预订 / 预算 / 备注）再次下载**直接取缓存**，不重新生成；任何一项变了（内容的哈希变了）就重新生成
- 并且 PDF 里的中文字体优先用生成速度快的字体（实测在本机：微软雅黑每次嵌入字体要 ~2 秒，思源黑体 ~0.7 秒）；没有这个字体的电脑自动退回原来的字体栈，只是慢一点
- 自动化：同一内容两次请求，第二次不再调用 PDF 渲染；内容变了会重新渲染

**S7 P1 · GPX 导出（v0.5 K4；KML 导出 v0.2 已做，KML / GPX 导入见 M12 S10）**
- 假设 我点行程页「更多」里的「导出 GPX」
- 那么 下载一个 `.gpx` 文件：每天一条轨迹（`trk`，名称「第 N 天 · 日期」，按行程顺序连线）+ 每个地点一个航点（`wpt`，名称、到达时间、简介）；颜色不在 GPX 里，不写
- 并且 只用核对过的坐标（WGS-84，GPX 的标准坐标系）；没有 `place_id` 的条目（午餐占位）不进文件；用户填的备注、预订确认码、预算、住宿**不写进文件**（和分享页同一个原则）
- 并且 多城市行程每天按所在城市取点，一个文件含全部天；历史版本也能导（`?version=n`）
- 接口：`GET /plans/{id}/itinerary.gpx`；用标准库生成 XML，不引入新依赖；用解析库反解校验航点数和轨迹数

## 数据与接口

- 分享选项存在 `shares` 表的 `share_packing / share_todos / share_notes` 三列（schema v11，老库自动加列，默认 0）。
- 接口（沿用 plans 命名）：`GET /plans/{id}/itinerary.pdf|md|html|ics|kml`（pdf 可带 `page_per_day=false`）、`GET /plans/{id}/route`、`POST|GET|DELETE /plans/{id}/share`、`GET /share/{token}`（公开内容）；前端公开页路由 `/s/{token}`。
- 令牌存在 SQLite 的 `shares` 表（schema v3，老库启动时自动升级）。
- PDF 用 Playwright；公开页是前端只读路由，API 用令牌鉴权。

## 验收方式

- **自动化**：各格式生成成功；ICS 用解析库反解并比对事件数；分享令牌失效后返回 410。
- **评测**：PDF 渲染后截图，用多模态模型按「布局、可读性、信息完整」打分（判断渲染结果，不是代码）。
- **前端**：你下载 PDF 看一遍、把 ICS 导进手机日历看一遍。
