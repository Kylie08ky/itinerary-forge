# M01 行程生成

> 版本：v0.1（单主题）→ v0.2（混选）→ v0.5（多城市）→ v0.9（多语言输出）
> 功能：F01 F02 F03 F04 F05 F06 · 来源：自有 + TripStar（异步任务、多城市）
> **现状（2026-10-28）**：v0.1–v0.3 与首页一句话填表（S10–S13）已做完；之后又长出**深度路线**（[09](../09-deep-routes.md)）：选一条路线代替主题，同样走「排程 → 骨架 → 质检 → 模型补说明」。多城市旅行（一份行程，[11](../11-multi-city.md)）也已做完；多语言输出默认不做。生成时一天按「上午 1、下午 1、晚上 1」排（[07 P20](../07-polish-backlog.md)）。

## 为什么

现在是「表单 → LLM 一次写完整份行程」，质量不稳，也没法解释为什么这样排。新流程是：**选主题 → 从地点库取候选 → 算法排程 → 质检 → 模型只写说明**。生成是后台任务，能看到真实进度，能降级。

## 范围

做：主题选择、基础约束表单、缺信息追问、异步任务与进度、降级、历史计划列表。
不做（本板块）：素材导入（见 M12）、编辑（见 M04）。

## 用户故事

- 作为游客，我想选一个主题（艺术 / 时尚 / 购物 / 博物馆 / 文娱 / 亲子 / 摄影 / 美食），再填日期和节奏，就得到一份能执行的行程。
- 作为游客，我想知道生成到哪一步了，关掉页面回来也能继续看。
- 作为游客，如果信息不够，我想被追问，而不是得到一份凭空编的行程。

## 验收场景

**S1 P0 · 单主题生成**
- 假设 我在首页选了主题「艺术」，目的地巴黎，日期 2026-10-03 到 10-06，节奏「均衡」，抵达 10:30、离开 18:00
- 当 我点击「生成行程」
- 那么 页面进入「生成中」，依次显示步骤：读取地点库 → 选点与排程 → 质检 → 生成说明（步骤名固定为 library / schedule / validate / narrate；选点和排程在同一个算法里完成，不拆成两步）
- 并且 完成后自动跳转行程页，共 4 天；中间的整天，主要点数量等于艺术主题配方里「均衡」对应的数量；抵达日 / 离开日窗口短，可以更少但不为空（当天太空时，会补不超过 2 个短的小点，小点不算主要点）
- 并且 所有主要点都是艺术主题的成员，质检徽标显示 0 error

**S2 P0 · 避开闭馆日**
- 假设 日期区间包含周二
- 当 生成完成
- 那么 卢浮宫、橘园不出现在周二；奥赛、罗丹不出现在周一

**S3 P0 · 刷新后仍可回看进度**
- 假设 我点击生成后，在「生成中」状态刷新了页面
- 当 页面重新加载
- 那么 仍显示同一个任务的进度（地址栏是 /tasks/任务号）；任务完成后自动进入行程页
- 并且 如果后台服务在生成中途重启，任务显示「生成中断，请重新生成」，而不是一直转圈

**S4a P0 · 日期只填一次（你的反馈）**
- 假设 我在首页填行程
- 那么 日期只有「抵达时间」和「离开时间」两个必填项（日期 + 时间），**没有单独的开始日期 / 结束日期**——开始日期、结束日期、天数都从这两个时间算出来，页面上显示「共 N 天」
- 并且 离开时间不能早于抵达时间；天数超出建议的 2–5 天时在离开时间下提示

**S4b P0 · 出行人与预算（你的反馈，批次 D 修订）**
- 假设 我在首页「行程信息」里添加出行人
- 那么 每个人填：**年龄**、**长居哪里**（不是 / 长居法国 / 长居其他欧盟或欧洲经济区国家，留学生常见）、**是否学生**；默认一位 30 岁、不长居欧洲、非学生的成人；最多 20 人
- 并且 还可以选填**预算上限**和**结算货币**（人民币 / 欧元；巴黎当地货币就是欧元，所以「当地货币」和「欧元」是同一项），金额按所选货币填
- 当 我点击「生成行程」并填了预算上限
- 那么 生成后系统用这些出行人的身份算出门票等费用；估算超出上限时，**自动把最贵的景点换成同主题、同区域、当天开门的更便宜备选**，直到不超或没得换，行程页明确写出「为了预算，把 A 换成了 B，省 ¥x」；你锁定的点和「必去」的点不动；换不动时写明还超多少；拿不到汇率又以人民币设上限时，写明「没法按预算调整」，行程照常生成
- 不填预算上限 = 和以前一样，不做任何预算调整

**S4 P0 · 缺信息追问**
- 假设 我没填抵达 / 离开时间或兴趣
- 当 我点击生成
- 那么 表单在对应字段下提示「必填」，不发起生成
- 并且 如果服务端发现还缺关键信息（比如没填住宿区域），返回的追问以列表形式显示在表单上方

**S5 P0 · 模型不可用时降级**
- 假设 本地模型没有启动
- 当 我生成行程
- 那么 仍然得到完整的分天行程
- 并且 页面顶部提示「说明文字由模板生成（模型不可用）」，质检和地图照常

**S6 P0 · 历史计划**
- 假设 我之前生成过 3 份行程
- 当 我打开「我的行程」
- 那么 看到 3 张卡片（标题、日期、主题、最近版本、质检状态），点进去回到对应行程
- 并且（v0.3）卡片上有「归档」；复制出来的行程标「副本」；归档的收进「已归档 (N)」，见 M04 S13 / S14

**S7 P1 · 生成失败的提示**
- 假设 候选地点不足以排满天数（比如 5 天只选了很小众的主题）
- 当 我生成
- 那么 页面明确提示「该主题的地点不够 5 天，已补充相邻主题的 N 个点」，并列出补充了哪些

**S8 P1 · 住宿区域作为锚点**
- 假设 我填了住宿区域「9 区」
- 当 生成完成
- 那么 每天的起点和终点靠近 9 区，首尾通勤时间在行程里可见

**S9 P1 · 混选主题（v0.2）**
- 假设 我在首页先选了「艺术」，再点「美食」
- 那么 两个主题都高亮，下面出现两个权重下拉（1–5，默认 3）；最多能选 3 个，选满后再点第四个没有反应；点已选的可以取消（至少留一个）
- 当 我点「生成行程」
- 那么 行程页顶部显示「主题：艺术 + 美食」；同一天里混搭，权重大的主题出现的主要点更多；行程里确实有美食主题的点
- 并且 「兴趣」框自动写成「艺术、美食」

**S10 P1 · 自然语言填表（修订 3：首页提示卡）**
- 假设 我在首页提示卡里写「10月20号去巴黎玩4天，两个人，喜欢艺术和咖啡馆，预算700欧，想去奥赛博物馆」，点「开始规划」
- 那么 下面的表单被填成：抵达 10月20日 10:00、离开 10月23日 18:00（4 天）；主题选中「艺术」（+ 美食，如果「咖啡馆」对上了）；出行人 2 位成人；预算上限 700、币种欧元；「偏好」步骤里的「必去」文字框写上「奥赛博物馆」、「想避开」文字框写上不想去的地点（和框里原有的内容合并去重，用户直接能改）；卡片下方的芯片行逐项写出系统是怎么理解的
- 并且 必去 / 想避开**只写在这两个文字框里**，不会再悄悄往折叠的「自定义候选地点」里另存一份（两处各存一份，用户删了文字框里的字、候选池里却还生效，就成了看不见的设置）
- 并且 **不会自动生成**：只填表，由你确认 / 修改后再点「生成行程」
- 并且 读不出来的项**不填**，并在「没读出来」里列出（比如没写日期 →「出发日期没读出来，请在下面选」）；读出来但不合规的照填并提醒（比如「玩 8 天」→ 填 8 天并提示「第一版建议 2–5 天」）

**S11 P1 · 规则读什么（确定性，不靠模型）**
- **日期**：「10月20日」「10月20号」「10/20」「20号」（月份取最近的一个）；年份取「今天之后最近的一次」（今天 10 月 22 日，说「10月20号」是明年）；**相对说法（2026-11-04 起读，场景 M37）**：「明天」「后天」「大后天」「今天」；「周六」「星期六」（今天之后最近的那个）；「这周六」「本周六」「下周六」「下下周六」；「周末」「这个周末」（最近的周六）、「下周末」；只说「下周」读成下周一、「这周 / 本周」读成今天——这两种读出来后在「提醒」里写明「按 11 月 9 日算，不对请在下面改」。**「五一」「春节」「国庆」这类节日、「下个月」（没说几号）仍然不读**，列进「没读出来」（节日每年的日期不同，读错代价大）；**日期永远由代码算，不让模型算**。「一周」「2周」这类是天数，不是日期。
- **相对日期的区间（场景 M40）**：「这周六到下周二」「周六到周二」「下周三到下周五」「明天到后天」读成开始 + 结束日期并算出天数；没写这周 / 下周的「到周二」取开始日期之后最近的周二；只说「周末」读成周六、周日两天并在提醒里写明（说了天数就按天数）。
- **出发地与来回交通（场景 M41）**：「从上海宝山出发」→ 出发地，填进「去程·出发地」和「返程·回到哪里」；「高铁 / 动车、飞机、火车、大巴、自驾 / 开车」→ 交通方式：只提一种（或带「来回 / 往返」）两头都用，提了两种按「去程 / 返程」或先后分去与回，只提了去程或返程的另一头不动。「我是这样理解的」里写出「出发地」「交通」两条。**只认明说的，不猜**；出发 / 到达的钟点说不出来，仍按表单预填的默认钟点，由用户改。
- **天数**：「4天」「四天」「4天3晚」「玩一周」（= 7）；「10月20日到23日」「10月20-23日」自动得到结束日；开始日 + 天数 → 结束日 = 开始 + 天数 − 1。
- **人数**：「两个人」「2人」「我们三个」「一个人」→ 对应数量的成人；「带孩子 5 岁」「小孩 5 岁」「儿子 8 岁」→ 加一位该年龄的出行人；「学生」「留学生」→ 把成人标成学生；一句里没提人数就**不动**表单里的出行人。
- **预算**：「预算700欧」「700欧」「700€」「预算5000元」「5000块」「人民币5000」→ 总预算上限 + 币种（欧 / € / EUR → 欧元；元 / ¥ / 块 / 人民币 / RMB → 人民币）；「人均」开头的金额不读（第一版只支持总预算，列进「没读出来」）。
- **主题**：主题名和同义词在原文里出现就选（艺术 / 博物馆 / 美食 / 咖啡馆 → 美食 / 购物 / 时尚 / 摄影 / 拍照 → 摄影 / 亲子 / 孩子 → 亲子 / 演出 / 歌剧 → 演出娱乐），按出现顺序最多 3 个，权重都是默认 3。
- **节奏**：「轻松 / 悠闲 / 慢慢逛 / 别太累」→ 轻松；「紧凑 / 赶 / 多去几个 / 特种兵」→ 紧凑；都没有就不动。
- **地点**：复用 M12 的地点库扫描 + 匹配（置信度「低」的不填，列进「没读出来」让你自己选）；「想去 / 一定要去 / 必须去」+ 地点 → 必去；「不想去 / 不去 / 避开 / 别去」+ 地点 → 不去；没有明确说法的地点 → 必去。

**S12 P1 · 模型只读规则没读出来的（意图理解，受限）**
- 规则读完后，如果本地模型可用，让它**只**补三样：① 把原文里的说法映射到**给定的主题清单**（比如「想逛逛街」→ 购物）；② 节奏；③ 一句话里的限制（「带老人少走路」「不吃辣」→ 限制，原文片段，最多 3 条）。模型的输出必须是约定的 JSON，主题 id 不在清单里的丢掉、限制超长的截断；**模型不碰日期 / 金额 / 人数 / 地点**。
- 笔记正文同样是不可信数据：提示词里把用户文字放在分隔块里并去掉分隔符，像指令的句子整句不给模型看（沿用 M12 S6 的 `drop_instructions`）；任何注入都不会改变表单以外的东西。
- 模型没开 / 超时 / 返回不合格式：只用规则的结果，页面提示「本地模型没开，只按规则读了」；**规则读到的照常填**。

**S14 P1 · 一句话读多城市（规格 11，2026-11-02）**
- 假设 我写「10月28日去北京玩3天，然后去西安玩3天，两个人」
- 那么 新建页的表单被填成两座城市：目的地「北京」，下面「添加下一座城市」里多出「西安」；北京 10月28–30日、西安 10月31日–11月2日（整趟 6 天）；出行人等其他项照常读。芯片行写「北京 3 天 → 西安 3 天」
- 并且 **城市按说的顺序，每座城市几天按字面读**；换城市默认在第二天（前一座城市最后一晚出发，交通按夜车估算），芯片行下面提醒一句「换城市默认在第二天，要当天换请在下面改西安的开始日期」
- 并且 说法覆盖：「北京3天然后西安3天」「先去北京玩三天，再去西安两天」「北京3天 → 西安3天」「北京3天，西安3天」；没写每座城市几天、但有总天数或日期区间（「去北京然后去西安，10月28日到11月2日」）→ 平均分，前面的多一天，并提醒「每座城市几天没写，先平均分」；每座城市几天写了但加起来和日期区间 / 「一共 N 天」对不上 → 按日期 / 总天数算，最后一座城市补齐并提醒
- 并且 最多 8 座城市（多的不填并提醒）；一句话里只有一座城市（「去巴黎玩4天，然后回国」）**完全按原来的单城市读**，不受影响
- 并且 读出来的城市库里没有的，和单城市一样马上去认 / 建（逐座，一座建好再开下一座）；**不会自动生成**，由你确认后再点「生成行程」
- 并且 **表单里已经是多城市时再写一句**：新这句只说了一座城市 → 去掉之前的后续城市；只说了日期（没有城市）→ 整趟一起平移；又说了两座以上 → 整个换成新的
- 读不出来的：「N 晚」的说法（不读，请在下面填）、「北京和西安各玩3天」这类合在一起说的（暂不读，按原来的单城市读第一座）

**S15 P1 · 「均衡」模式按全城名气从高到低选点（2026-11-04，场景 M35、M36）**
- 假设 主题是「均衡」（没有特定倾向），这座城市的地点有名气分（M02 S9，现建城市）
- 那么 点的权重按全城名气排名定：前 10% 权重 5、10%–25% 权重 4、25%–50% 权重 3，其余 2（**类别怎么分配见 S15b**）；仍然要路线不折返、避开闭馆日、遵守节奏和每天的时间
- 并且 选了具体主题（不是均衡）时不变，仍按主题；没有名气分的城市（人工策展的老城市）不变
- 并且 每天的「选点理由」写明依据：「选了「开元寺」：名气——维基百科 31 种语言版本，全城第 3」；行程页的「生成说明」里加一条「选点标准」：均衡模式按维基百科语言版本数排序，同一天同类别不超过两个，并说明它只代表知名度
- 你在前端验收：M35 泉州均衡 3 天，每天的选点理由里是「名气 · 第 N」且排名靠前的点都被排进去了（除非闭馆）；M36 行程页「生成说明」里有选点标准一条


**S15b · 「均衡」要覆盖不同种类（2026-11-04 你反馈「泉州推荐的全是寺庙」，场景 M39）**
- 假设 「均衡」模式、这座城市有名气分（S15）、有好几个主题（寺庙 / 博物馆 / 山水 / 美食……）
- 那么 **每个主题都要出现**：整趟行程里每个主题（有点的）至少排 1 个（天数够的话），其余名额按主题平均分；**每个主题内部按名气从高到低选**；同一天里已经有某个主题的点时，第二个同主题的点要让一让（软规则）
- 并且 这取代 S15 里「全城统一按名气排」：名气只决定「同一类里谁先」和「类别之间名额相同时谁先」，类别覆盖优先
- 你在前端验收：泉州均衡 3 天，行程里不全是寺庙，有山水（清源山）、博物馆、古迹、桥 / 地标等不同种类


**S13 P1 · 接口与边界**
- `POST /intake/nl`，请求 `{ "text": "…", "today": "2026-10-22"? }`（`today` 只给测试用，默认用后端的今天，`ATP_TODAY` 可固定）。文本为空 → 422；超过 500 字 → 422（「最多 500 字」）。无状态：**不存正文**，只返回解析结果。
- 返回 `{ fields, understood, missing, notes, model_used }`：`fields` 只含读到的项（多城市时另有 `stops`：按顺序的 `[{destination, days, start_date?, end_date?}]`，见 S14；`start_date` / `end_date` / `days` / `theme_ids` / `travelers` / `budget_cap` / `currency` / `travel_style` / `must_go_ids` / `avoid_ids` / `must_go` / `avoid` / `restrictions`；后两项 `must_go` / `avoid` 是前面两项对应的地点库中文名，给「偏好」里的文字框用，后端能按名字认回同一个地点）；`understood` 是给人看的中文句子；`missing` 是没读出来的项；`notes` 是提醒（天数不在 2–5 天等）。
- 评测：`scripts/eval_intake.py`（10 句标注集 + 真模型）：规则项（日期 / 天数 / 预算 / 人数 / 地点）准确率 100%，主题 / 节奏召回；注入句子不改变结果。

- 实体：`Trip`、`Task`、`Version`（见 [03](../03-data-model.md)）。
- 自然语言填表：`POST /intake/nl`（见 S13）；实现在 `app/intake_nl.py`，复用 `app/notes` 的地点库扫描 / 匹配。
- 接口（沿用现有的 plans 命名）：`POST /tasks`（返回 `task_id`，202）、`GET /tasks/{id}`（状态与四个步骤的进度）、`GET /plan-cards`（我的行程卡片）、`GET /plans/{id}`（行程详情）。
- `GET /plan-cards` 的读库开销不随行程数增长：一次查询取回所有行程的最新版本，不能每份各开一次数据库连接（手机底栏每次进页面都要请求它；测试 `tests/test_plan_cards_cost.py`）。校验里认城市（名字→城市一次查表）和读别名表（文件没改就不重读）也不随调用次数重复做（`tests/test_validator_cache.py`）；城市列表重新加载后自动用新的。
- 步骤名固定为 `library` → `schedule` → `validate` → `narrate`，前端按步骤名显示文案。
- 存储：Python 自带的 SQLite（WAL 模式），行程、版本、任务各一张表；旧的 data/plans/ 文件行程在首次启动时自动导入。

## 验收方式

- **自动化**：任务状态机测试；用假模型和空模型各跑一遍 S1、S5；S2 对三个人设各跑一次并断言没有闭馆日冲突；回归集新增排程用例。
- **评测**：主题契合度——生成结果里主题成员占比 ≥ 阈值（先设 80%）。
- **前端**：Playwright 脚本走 S1、S3、S5，并截图；你按 S1–S6 手点一遍。
