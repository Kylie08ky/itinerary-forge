# M02 地点库与候选池

> 版本：v0.1（地点库、核对状态）→ v0.2（候选池、地点详情）→ v0.7（收藏库）
> 功能：F07 F08 F09 F10 F11 · 来源：自有 + TREK（地点池、地点详情）
> **现状（2026-10-28）**：✅ 已做完：巴黎 91 个点、8 个主题；候选池、地点详情卡、图片与简介（Wikimedia 署名）、封面大图。地点现在还有 `setting / zone / name_local / season（当季活动）/ meal（用餐）/ open_access` 等字段，见 [03 第 4 节](../03-data-model.md)。收藏库（v0.7）暂缓。

## 为什么

地点库是排程的原料，也是事实的来源。你说过「核对细节不应该由我来做」，所以每个事实都要带**自动核对状态**，并且在页面上让你点一下就能验证。候选池是「这次旅行我们想去哪」的清单，后面的笔记导入、多人投票都落在这里。

## 范围

做：地点库浏览、主题浏览、地点详情卡、核对状态、候选池（勾选 / 权重 / 必去 / 避开）。
不做（本板块）：地点搜索（M05）、笔记抽取（M12）、多人投票（M11）。

## 用户故事

- 作为游客，我想按主题浏览地点，看每个点是什么、为什么值得去。
- 作为游客，我想一眼知道某个地点的官网链接、闭馆日、坐标是不是靠谱。
- 作为游客，我想把想去的点放进候选池，标出「必去」和「不想去」，并调整重要程度。

## 验收场景

**S1 P0 · 按主题浏览**
- 假设 我打开「地点库」页
- 当 我点击主题「时尚」
- 那么 看到该主题的地点卡片，主要点在前、填充点在后，每张卡显示名称、区域、类别、建议时长

**S2 P0 · 官网链接能打开且已核对（只有需要订票的地点才有官网链接）**
- 假设 我打开卢浮宫（需要订票）的地点详情
- 当 我点击「官网」
- 那么 新标签页打开的是卢浮宫官网
- 并且 详情里写着「官网链接已于 2026-10-08 自动核对 ✓」；核对失败的地点显示「官网链接待核实」而不是显示链接

**S2b P0 · 无需购票的地点只给地址**
- 假设 我打开一个无需购票的地点，比如杜乐丽花园、Citypharma 药妆店、玛黑区步行街
- 那么 详情和行程条目里**没有官网链接**，只有一行「地址：…」（没有门牌号的街区 / 步行街写到街道和邮编）
- 并且 每个地点都有地址；有线上购票渠道的地点（必须线上，或线上+现场），除地址外还有官网购票链接和购票方式标签（见 M06）
- 说明：这是你的决定。没有购票渠道的地点，官网大多是介绍页或线上商城，对游客没用；地址才是出发时要用的

**S3 P0 · 闭馆信息可见**
- 假设 我打开奥赛博物馆详情
- 那么 显示「周一闭馆」；蓬皮杜中心显示醒目的「整修闭馆中」，并且在任何主题的推荐里都不作为主要点出现

**S4 P0 · 核对状态分级**
- 假设 地点库里有些点的坐标 / 开放时间尚未核对
- 那么 这些字段旁显示「待核对」灰色标记，已核对的显示绿色勾和日期；页面顶部汇总「N 个点已完全核对，M 个待核对」

**S5 P1 · 候选池**
- 假设 我在首页选好主题，展开「自定义候选地点」
- 那么 看到所选主题的全部成员（名称、区、主要点 / 辅助点、默认权重），每行有「默认 / 必去 / 不去」三选一和权重下拉；设置过的行左边有绿 / 红色条，标题处显示「已设置 N 项」
- 当 我把一个点标为「必去」、另一个标为「不去」后生成
- 那么 行程里一定包含必去的点、一定不含不去的点；权重 4–5 的点优先入选，1–2 的点只在排不满时才用
- 并且 标成「不去」后权重下拉禁用（两者互斥）

**S5b P1 · 在地点库里搜索并加入候选池**
- 假设 我在候选池的搜索框输入「Orsay」
- 那么 列出库里匹配的点（名字 / 英文名 / 别名 / 区域都能搜），点「加入并标为必去」后它出现在候选列表（标注「你搜索加入的」），搜索框清空
- 并且 搜不到时提示「地点库里没有找到」，并说明库外地点暂不支持（没有开放时间和闭馆日，没法可靠排进行程）

**S6 P1 · 候选池为空时用主题默认**
- 假设 我没动候选池
- 那么 生成使用所选主题的全部成员作为候选

**S7 P1 · 地点详情卡（v0.2 不含图片，v0.3 批次 G 加图片与简介，见 S7b）**
- 假设 我点行程里某个景点的标题，或候选池里的地点名
- 那么 弹出详情卡：地址、交通、建议停留与最佳时段、票价、闭馆日、购票方式（三档标签 + 购票提示）、参观重点、属于哪些主题；按 Esc 或点 ✕ 关闭
- 并且 官网链接只在「必须线上购票 / 建议线上购票」的地点出现；无需购票的只有地址
- 并且 底部逐项显示核对状态：「坐标 / 闭馆日 / 官网链接已于 某日 自动核对」，没核对的显示灰色「待核对」
- 注：图片与简介见 S7b

**S7b P1 · 地点图片与简介（v0.3 批次 G；你已拍板：缩略图提交进仓库、简介用中文维基百科摘要前两句、显示在详情卡 / 时间轴缩略图 / 地图气泡）**
- **S7b-1 详情卡**：标题上方是一张照片（宽屏裁切），照片下面一行小字**署名**：「摄影：作者 · 授权（如 CC BY-SA 4.0，带链接）· 来源 ↗（Wikimedia Commons 的文件页）」；标题下面是**简介**（中文维基百科摘要的前两句，不超过 200 字，在句号处截断），简介下面一行小字「来源：中文维基百科 · CC BY-SA 4.0 ↗」（链接到那个条目）。署名和来源**永远和图片 / 简介一起显示**，不能折叠、不能省略。
- **S7b-2 没有就不显示**：没有合适图片的地点不出图片区、也没有破图；没有中文条目的地点不出简介（不编、不用模型写）。图片文件加载失败时图片区整块收起，署名一并收起。
- **S7b-3 时间轴缩略图**：行程里每个有图片的景点，右侧有一张 72×72 的缩略图（懒加载，圆角）；点缩略图和点标题一样打开详情卡（署名在详情卡里）；缩略图悬停提示「摄影：作者 · 授权」。**公开分享页也有缩略图、地图气泡照片和详情卡里的照片**（你验收后改的：分享给朋友看，有图更直观）；PDF、长图、Markdown 不放图。
- **S7b-4 地图气泡**（F32）：全程地图和每天地图上，鼠标悬停 / 手机点按标记，弹出气泡：缩略图 + 名称（没有图片的只有名称）；点标记 / 气泡仍然打开详情卡。**气泡永远完整显示在地图里**（你验收后提的：靠边的标记气泡被地图边缘裁掉一截）：气泡打开后量一下，放得下就不动；放不下就换方向（上 → 下 → 右 → 左，取第一个放得下的）；四个方向都放不下（地图比气泡还小）才选超出最少的并平移地图。不用「先平移地图」，因为标记会从鼠标下面移走、气泡就消失了。电脑的全程地图、每天的小地图、手机上都一样。
- **S7b-5 离线**：图片是本地文件，后端按 `/media/places/{地点编号}.{扩展名}` 提供（一天的缓存头；重新跑脚本换了图时，Service Worker 的缓存名要升一版）；Service Worker 对它们 cache-first，所以先联网看过的图，离线也有。
- **S7b-6 数据与合规（硬规则）**：图片和简介的数据在 `data/places/media.json`（每个地点：`image{file, title, source_url, author, license, license_url, width, height, checked_at}` 和 `intro{text, source_url, source_name, license, license_url, checked_at}`），文件在 `data/places/photos/`。**只用 Wikimedia Commons / 中文维基百科**（Openverse 等其它图库的搜索接口目前不可用 / 要注册 Key，见下面的「待你确认」）；图片授权必须在白名单里（CC0、公有领域、CC BY 各版本、CC BY-SA 各版本），作者、授权、来源链接缺一项就不收；**不由模型挑图或写简介**。
- **S7b-7 选对地点的自动保护**：脚本按英文名在维基百科搜索，候选条目要**同时满足两条**才采用：**名字和地点对得上**（去掉「博物馆 / 公园 / 桥」这类泛称后至少有一个词相同）、**坐标落在地点库坐标 1000 米内**——标题里带「地铁站 / 剧院 / 动物园」这类说明它是别的东西的词也不采用（除非地点自己的名字里就有）；几个候选都满足时取名字最像的；只看坐标会把旁边的地铁站当成景点，只看名字会把别处的同名条目拿来；缩略图超过 450KB 的改要更窄的版本（480、360），仍然太大就不收图片（简介照收）；没有坐标的条目不采用；匹配不上的地点就是没有图片 / 简介。**条目没有可用主图的地点，再到 Commons 里直接搜**（你验收后提的：没有图片的地点换别的方式找图）：全文搜索「名字 + Paris」，再加上附近 200 米内有坐标的照片；文件名要和地点名对得上、不是标志 / 地图 / 菜单 / 海报 / 绘画，文件的分类或描述里要写着 Paris，授权和尺寸检查同上。脚本用 `scripts/fetch_place_media.py`，只发公开的只读请求、1 次 / 秒，带说明用途的 User-Agent；脚本只在我手动跑的时候联网，应用运行时不访问 Wikimedia。

**S7c P1 · 封面大图（修订 3，M02 的延伸；你已拍板：只用我们自己的 CC 授权实拍图）**
- **用途**：首页全屏背景、行程页封面舞台。地点库里原有的缩略图（S7b，640 宽）铺满全屏会糊，所以对**少数标志性地点**另取一张 ≥ 1600 宽的大图。
- **来源与授权**：只取 `data/places/media.json` 里**已经通过授权白名单**的那张图（同一个 Commons 文件，只是请求更大的尺寸），作者 / 授权 / 来源链接沿用并随图显示；不引入新的图片来源。
- **挑选规则**（脚本自动挑，人工可用 `hero_exclude` 排除并写原因）：原图宽 ≥ 2400、宽高比 ≥ 1.35（横图）、文件 ≤ 900KB（超过就换 1600 宽）；标志性地点优先（埃菲尔铁塔、卢浮宫、巴黎圣母院、凯旋门、圣心大教堂、奥赛博物馆、凡尔赛宫、加尼叶歌剧院、孚日广场、杜乐丽花园……），挑不出合格图的地点就没有大图。
- **数据**：`data/places/hero.json`（每个地点：`image{file, title, source_url, author, license, license_url, width, height, checked_at}`）+ `data/places/hero/` 下的文件；脚本 `scripts/fetch_hero_images.py`（只在手动跑时联网，只读请求、1 次 / 秒、带说明用途的 User-Agent）；后端 `/media/hero/{文件名}` 提供（一天缓存，文件名白名单正则）；`GET /places/{id}` 和地点列表的 `media` 里多一个 `hero`（没有就没有）。
- **前端规则**：首页背景按固定顺序取第一个有大图的标志性地点；行程页封面按「这趟行程里主要点优先、有大图的第一个」取；都没有 → 退回渐变。署名永远显示（S19）。
- **验收**（自动化）：每条记录的文件存在、宽度 ≥ 1600、体积 ≤ 900KB、授权在白名单、作者 / 来源齐全；`hero` 只出现在有记录的地点上；`/media/hero/` 不能目录穿越。

## 数据与接口

- 实体：`Place`、`ThemePack`、`CandidateEntry`、`Place.verification`（见 [03](../03-data-model.md)）。
- 接口：`GET /places`、`GET /places/{id}`、`GET /themes`、`GET /themes/{id}`、`GET/PUT /trips/{id}/candidates`。
- 核对由 `scripts/verify_library.py` 产出，结果合并回数据；页面只读展示。

**S9 P1 · 名气分：每个地点带「维基百科有多少种语言版本」（2026-11-04，场景 M34）**
- 假设 你想知道系统为什么觉得一个地点「有名」、按什么排的
- 那么 现建城市的每个地点存一个名气分：**维基百科 / 维基数据里这个条目的语言版本数**（`fame = {sitelinks, source: wikidata, checked_at}`）。这是一个公开、可以去核对的数，不是模型打的分，也不用高德的数据
- 并且 地点卡里写「名气：维基百科 31 种语言版本 · 全城第 3」（排名按这座城市里有名气分的点从高到低算）；没有名气分的点（人工策展的老城市、你从高德搜来加的点）不写，不编
- 并且 已经建好的城市用脚本 `scripts/backfill_fame.py` 补上名气分（只读维基数据，不改别的事实）；之后新建的城市建的时候就带
- 并且 **热度（场景 M42）**：同时存「近 12 个月中文维基百科的浏览量」（`fame.views`、`fame.views_period`，维基媒体公开统计，只算真人），地点卡写「近一年约 1.4 万次浏览」；名气（语言版本数）相同的点，浏览量高的排前面。没有中文维基条目的点不写浏览量
- 并且 **维基导游（场景 M43）**：`voyage = {kind, url, revid, checked_at}`，表示维基导游（Wikivoyage，CC BY-SA 4.0）的城市页里列了这个地点；地点卡写「维基导游推荐」并链到那一页。只存标记和链接，不存它的文字
- 并且 语言版本数只说明「被多少种语言的维基百科收录」，不等于好玩；它决定「均衡」模式下谁先排（见 M01 S15），不影响其他事实（闭馆日、价格）


## 验收方式

- **自动化**：地点库装载与完整性（已有）；核对结果合并后 `verification` 字段齐全；API 返回包含核对状态。
- **数据核对**：脚本全量跑一遍，失败项进报告；官网链接 403（拦机器人）的，用浏览器自动打开确认标题。
- **前端**：你按 S1–S4 手点；Playwright 断言「官网」链接的 `href` 指向地点的 `official_url`，并截图。

## 待你确认

1. 官网链接被网站拦截、脚本无法确认时（如奥赛、铁塔），页面显示「已核对」还是「待核实」？默认：由我用浏览器实际打开确认后才标「已核对」，否则标「待核实」。
2. ~~简介和图片先用维基百科 / Wikimedia（有明确授权），可以吗？~~（你已拍板：可以；缩略图提交进仓库；简介用中文维基百科摘要前两句）
3. 还有地点找不到授权图时，是否注册一个图库的 Key（Flickr / Unsplash / Pexels，免费，Key 只放 `.env`）？Openverse 的搜索接口试过，目前超时。Google / Bing 图片搜索不行：没有授权信息，用了有版权风险。
