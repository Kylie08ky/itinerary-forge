# M11 协作

> 版本：v0.7（成员、权限、投票、实时同步、群聊 / 评论）
> 功能：F63 F64 F65 F66 F67（另 F11 跨行程收藏库、F56 分摊依赖本模块）· 来源：TREK（协作、成员、聊天、投票）

## 为什么

你的核心场景是「我和朋友一起做计划」。协作先做成**异步、清晰**：邀请 → 各自加想法 → 投票 → 敲定。

## 范围

做：邀请成员（链接，含无账号游客）、4 种角色（所有者 / 编辑 / 评论 / 只读，不做 16 动作矩阵）、评论与简易群聊、候选项投票与多人收藏合并、活动日志、实时同步（WebSocket，同一版本 v0.7 但作为最后一项交付）、并发编辑冲突提示。
说明：清单里 F66 含群聊；若实时同步延期，则以刷新 / 轮询兜底，仍满足验收。

## 验收场景

**S1 P1 · 邀请与加入**
- 假设 我在行程里点「邀请」
- 那么 得到邀请链接；朋友登录后点开即加入为「编辑」；我可改角色或移除

**S2 P1 · 只读成员不可改**
- 假设 朋友角色为「只读」
- 那么 其页面隐藏编辑控件；直接调接口返回 403

**S3 P1 · 评论**
- 假设 我在「圣心大教堂」条目下评论「这天可能太累」
- 那么 其他成员看到评论徽标，点开可回复

**S4 P1 · 候选投票**
- 假设 候选池里有 6 个点
- 当 3 位成员各自为想去的点点赞
- 那么 候选池按票数排序，排程时票数作为权重（M02）

**S5 P1 · 活动日志**
- 假设 朋友改了第 2 天
- 那么 「活动」里显示「小王 把圣礼拜堂从第 1 天移到第 3 天」

**S6 P2 · 同时编辑冲突**
- 假设 两人同时改同一天
- 那么 后保存者看到「对方刚更新了这一天」并可选择合并或覆盖

## 数据与接口

- 实体：`Member{trip_id, user_id, role}`、`Comment`、`Vote`、`Activity`（见 [03](../03-data-model.md)）。
- 乐观并发：`If-Match` + 版本号。
- 依赖：M14 账号。

## 验收方式

- **自动化**：权限矩阵（角色 × 接口）；并发冲突返回 409。
- **前端**：你用两个浏览器 / 账号按 S1–S5 点。
