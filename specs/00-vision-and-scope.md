# 00 愿景与范围

> 状态（2026-11-06）：愿景和原则没变；**范围按「作品集演示 + 自己和朋友用」收窄了**：v0.1–v0.4、巴黎打磨、周边一日游、深度游学路线、任意目的地、高德（国内地图 / 搜索 / 通勤）、多城市（一份行程）已做完；协作与账号、AI 伴游、小红书合集、GPX / KML 暂缓到交付之后；中英双语、MCP / TOTP 默认不做。进度见 [05](05-progress-checklist.md)，白话版见 [`docs/progress-overview.md`](../docs/progress-overview.md)。

## 1. 为什么做

中国游客自己规划国内外旅行，现状是：在小红书刷安利 → 手动记地点 → 查开放时间和预约 → 在地图上拼路线 → 订票。每一步都耗时，而且容易踩坑（周一闭馆、没预约进不去、路线折返）。

我们要做的是一个**旅行计划生成 Agent**：把「主题 / 笔记 / 收藏」变成一份**可执行、可核对、可修改、可交付**的行程。

## 2. 给谁用

- **前期**：作者和朋友自用；**后期**开源给所有人。所以：不替别人付 API 费用（每个部署者用自己的 Key，缺 Key 时降级）；界面只做中文和英语。
- 2–5 位中国游客朋友共同规划一次旅行，目的地国内外都有。
- **使用场景**：规划在电脑上做，**旅途中在手机上随时查看和修改**，所以手机体验是一等公民，不是附属品（见 M15）。
- **前提假设**：用户能自己登录景点官网订票，也能访问国际网站。所以系统给出「订票清单 + 官网链接 + 最晚订票时间」，**不代订、不支付**。

## 3. 产品形态：三种输入，一条流水线

```
 A 主题式（选主题）      ┐
 B 粘贴笔记 / 链接      ├─►  候选地点池 ─► 排程（分天·路线·开放时间）─► 质检 ─► 交付 ─► 修改 ─► 新版本
 C 小红书收藏合集（后做）┘
```

LLM 负责理解意图、从笔记里抽地点、写说明；**确定性的事交给算法**：分天、路线、开放时间、闭馆日、预约、校验。

## 4. 范围：参考 TREK 与 TripStar 的功能

你要求把 TREK 和 TripStar 的功能都做上。规格的做法是：

- **全部功能都列进** [功能清单](01-feature-inventory.md)（原 101 条，做的过程中又长出 10 条），不悄悄丢弃任何一条。
- 每条标「做 / 后做 / 待你拍板」和目标版本。「待你拍板」是我建议不做或低优先的，**理由写明，你可以推翻**。
- 实现方式：**按功能思路自己重写，不拷贝它们的代码**（见第 7 节）。

坦白一点：TREK 的源码有 47 MB TypeScript、23 种语言、插件系统、199 个 MCP 工具，是一个团队做了一年多的成品。全部做完是一个很长的路线，所以规格按版本分期，每个版本都能独立使用，并且每个版本末尾你都能在前端验收。

## 5. 设计原则

1. **确定性与概率性分离。** 能算准的不让模型猜。
2. **事实只信策展数据。** 官网链接、闭馆日、长期闭馆、价格只来自带核对记录的数据；模型给的网址一律不用。
3. **每个事实带核对状态。** 页面上能看到「官网链接已于某日自动核对」，让你点开就能验证。
4. **降级而不是失败。** 模型不可用，仍能排出行程（说明文案用模板）；路线服务不可用，用直线距离估算并标注「估算」。
5. **用户永远能改。** 任何生成结果都能手动调整，改完自动重新质检。
6. **前端即验收。** 每个场景都写成你在页面上能看到、能点的东西。

## 6. 非目标

- 代订票、支付、酒店实时比价。
- 替用户登录任何第三方网站。
- 面向公众的商业化运营（账号体系先做到小团队够用）。

## 7. 已做的决定（可推翻）

| 决定 | 理由 |
|---|---|
| 不 fork TripStar，在现有仓库重构 | 小红书推迟后它的主要价值用不上；GPL-2.0 会让整个项目被迫 GPL；它前端是 Vue，我们是 React |
| 前端保持 React + TypeScript | 已有时间轴、对比、地图等成果 |
| 第一个目的地只做巴黎 | 数据层和主题包已有基础。**结果**：巴黎做完整（91 个点、8 个主题、6 条深度路线）；之后由你的真实旅行带出了斯图加特 / 亚琛周边一日游（开放数据草稿）；国内城市暂缓 |
| 地图：境外 Google，境内高德，按**目的地所在地区**选供应商 | 你的要求；TripStar 是按「有没有配 Key」选，不一样 |
| 小红书：先做「粘贴笔记」，收藏夹读取推迟到 v0.6，且先做可行性验证 | 风险最大的一块；Cookie 抓取有账号和合规风险。**结果**：粘贴笔记和链接（含用你自己的 Cookie 读小红书单篇）已做完，收藏夹读取仍暂缓 |
| 只借思路、不拷贝 GPL / AGPL 代码 | 许可证 |
| 不做：3D 地图、AirTrail、OIDC、Helm、其余 20 种语言（只做中 / 英） | 你已拍板 |
| 后做：多币种 / CSV / 分摊、行李重量、足迹类模块（可联动「世界迷雾」，需 spike） | 你已拍板 |
